**Validated numbers — copy, do not retune:** edge fade `0.20 + 0.80*exp(-ageSeconds/40)`,

in-pfm rate and the comet/tween math is dt-based so it survives the change.

**Color quantization is load-bearing, not a style choice.** `quantRGB` in the POC's
`canvas.go` rounds every emitted channel to 32 levels (step 8, round-to-nearest) at the single
emit boundary, and it MUST survive the port applied to every color the tab emits. Reason:
GPU-accelerated terminal renderers (VS Code's xterm.js WebGL is the proven case) rasterize one
texture per (glyph, color) pair into an atlas shared across every terminal in the window;
continuous 24-bit fades mint thousands of new entries per second, the atlas recycles pages,
and *sibling terminals* render corrupted glyphs — observed live on 2026-08-27. Quantization
bounds the palette (~215 distinct colors per frame, ~669 over 13 s, measured) and merges SGR
runs; keep it, do not widen the step. **But it is not sufficient:** the corruption reproduced
on 2026-08-27 with quantization active — braille glyph diversity at the POC's 33 ms redraw is
enough on its own. Upstream report: microsoft/vscode#332859. The POC's answer (2026-08-27,
same day) is **differential rendering**: `Canvas.Flush` keeps the previously flushed frame
(`prev []cell`) and emits only changed cells — measured 13.3% of a full frame per moving tick
and 0 bytes idle, locked by `flush_diff_test.go` — plus a vscode-safe mode (auto on
`TERM_PROGRAM=vscode`: 66 ms tick, quant step 16, `· safe` in the HUD). Consequences for the
port: bubbletea's own diff-paint plays the diff role in pfm and the 125 ms tick is already a
4× lighter load, but neither is *proven* safe against this bug — the known-good demo surfaces
remain a standalone terminal emulator or a VS Code window with
`terminal.integrated.gpuAcceleration: "off"`. A corrupted window recovers via reload.

### Task #1 — `comms` table + shared-store API

One new table in the shared operator DB plus its typed accessor pair. **Why:** every recorder (tasks 2–4) and the reader (task 6) need one authoritative, cross-process store; the shared DB is where durable operator state already lives and every sending process already opens it.

**Routing:** pfm. **Build agents:** dev (spec-execution/sonnet), qa after.

**Key behaviors:**
a. `RecordComms` inserts one row; on a degraded store it returns the degraded error wrapped `"record comms event: %w"` — never a silent no-op (the `Kill` pattern at `shared.go:181-196`, NOT the `AddChild` nil-swallow at `:357-359`).
b. `CommsSince` returns newest-first events with `at_ns >= since`, capped by `limit`; on a degraded store it returns the wrapped degraded error. An empty healthy result is `[]` + nil error — absence and failure are distinct at the API surface.
c. Concurrent writers ride the existing WAL + `busy_timeout=10000` pragmas (`shared.go:121-139`); no new locking.

**Data model:** appended to the `schemaDDL` const at `internal/shared/shared.go:49-74` (idempotent DDL is this DB's incumbent migration mechanism — it has no numbered migrations; the private DB's `migration_v9.sql` is NOT touched):

```sql
CREATE TABLE IF NOT EXISTS comms(
  id              INTEGER PRIMARY KEY,
  at_ns           INTEGER NOT NULL,
  kind            TEXT NOT NULL CHECK(kind IN ('inject','group','spawn')),
  sender_session  TEXT NOT NULL DEFAULT '',
  sender_label    TEXT NOT NULL DEFAULT '',
  sender_uuid     TEXT NOT NULL DEFAULT '',
  target          TEXT NOT NULL DEFAULT '',
  receiver_socket TEXT NOT NULL DEFAULT '',
  receiver_pane   TEXT NOT NULL DEFAULT '',
  group_name      TEXT NOT NULL DEFAULT '',
  members         TEXT NOT NULL DEFAULT '',
  message         TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS comms_at ON comms(at_ns);
```

`message` is the full verbatim text (user decision — no cap, no spill). `members` is a JSON-encoded `[]string` (matched member names, group kind only). `target` is the raw target string as the sender gave it (label / glob / group name / child socket).

**Contracts:** exports `shared.CommsEvent`, `(*Store).RecordComms`, `(*Store).CommsSince` — consumed by tasks 2, 3, 4, 6. No shim, eval-line, or MCP type change.

**File plan:**

### Task #5 — `compose` derives the cosmos graph

A pure function turning fleet rows + comms events into nodes and edges. **Why:** `compose/` is the side-effect-free composition layer (its charter); rendering must consume a finished graph, never raw SQL.

**Routing:** pfm. **Build agents:** dev, qa after (table-driven — this is the K3 single implementation of graph derivation).

**Key behaviors:**
a. `BuildCosmos(rows, events, nowNS)` returns nodes for: every event participant (matched to a live `Row` where possible) and every group named by a group event. Live fleet rows with no traffic are NOT nodes — cosmos maps conversation, `ls` already maps existence.
b. Node identity matching, in order: `sender_uuid`/`sender_session` ↔ `Row.ID`; `receiver_socket`+`receiver_pane` ↔ `Row.Socket`+`Row.PaneID`; `sender_label`/`target` ↔ `Row.Name`. Unmatched participants become ghost nodes (`Live=false`) keyed by their strongest identifier — a dead chat keeps its place in the universe.
c. Edges aggregate per (from, to, kind): `Count`, `LastNS`, `LastMessage` (for the detail line). Group events yield sender→group edges plus group→member edges for each JSON member; spawn events yield parent→child lineage edges (skipped when parent is `""` per 4b).
d. Events window: caller passes only events within `cosmosWindowNS = 24h`; `BuildCosmos` trusts its input and does no clock reads (the `Snapshot` doc law `types.go:61-62`: rendering never probes the clock).
e. A ledger read error arrives as `CosmosGraph.Err` (set by task 6, threaded through untouched) — the graph carries the failure to the surface rather than masquerading as an empty sky.
f. Malformed `members` JSON in one row degrades to that event contributing only its sender→group edge, plus `CosmosGraph.Warnings` gaining one string — a bad row never sinks the frame.

**Data model:** none (in-memory).

**Contracts:** exports `compose.CosmosNode{Key, Label, Engine string; Live, Killed, Group bool; LastNS int64}`, `compose.CosmosEdge{From, To, Kind string; Count int; LastNS int64; LastMessage string}`, `compose.CosmosGraph{Nodes []CosmosNode; Edges []CosmosEdge; Err string; Warnings []string}`, `func BuildCosmos(rows []Row, events []shared.CommsEvent, nowNS int64) CosmosGraph`. Consumed by tasks 6 and 7.

**File plan:**
- `pfm/internal/compose/cosmos.go` — CREATE: the types and `BuildCosmos` above; deterministic ordering (nodes by Label then Key; edges by LastNS desc) so goldens are stable.

**Boundaries & anchors:** NOT included: layout, colors, animation (task 7's). Anchors: `Row` fields `compose/types.go:113-146`; package charter `pfm/CLAUDE.md` ("side-effect-free row composition").
