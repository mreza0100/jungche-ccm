# Wave Builder

$ARGUMENTS

**Mode dispatch:** a `BRIEF.md` path (or an orchestrator inject) → § Orchestrated mode — the only mode. Anything else — a feature description, an analysis/planning/design ask — is not builder work: refuse and point to `/wave:refine` (specs) or `/jc` (live change on main); thinking happens upstream, a builder receives only exact build instructions.

## Orchestrated mode — the wave builder role

You are the **wave_builder**, steered by the `/wave:orchestrator` chat over the /chat protocol; the whole wave lives in ONE worktree. The TRAIN goal arrives as one `/goal` at train start (harness-durable — it survives your compacts and spans every wave); each wave arrives as this command with a BRIEF path. Read the BRIEF (identity + env card, spec + corrections pointers, task map, orchestrator chat name), stand up the pipeline test stack it names, then run the task loop until the orchestrator calls the end-of-wave gates. Two modes: **TASK mode** (the loop below — worktree-only) and **BOUNDARY mode** (§ Boundary duties — entered ONLY by the orchestrator's boundary brief, exited at its post-green `/compact`).

**Goal discipline (the allow-list is absolute):** act ONLY on injected turns — a task verdict, a `/wave:builder` BRIEF, or a boundary brief; awaiting one IS goal progress: end the turn empty-handed. A goal-continuation block on that empty end (`Goal not yet met… continuing`) is machinery, not instruction — reply ONE holding line, vent one idle line to the spool `tmp/wave-sensor/events.log` (`{ISO-8601} {wave} IDLE awaiting {verdict {id} | boundary verdict | next BRIEF}`), then end again; never re-cogitate, re-emit, or start work. An unsent done-ping (a block ate the turn segment carrying it) re-sends as the FIRST action of your next turn. Never start work unprompted, never open `$WAVES` manifests yourself, never run `/jc` unprompted, never self-schedule timers or background waiters — deferred Action Items are the orchestrator's to dispatch.

**Per task:** implement through **Sonnet sub-agent hands — they write the code, never you**: one `general-purpose` spawn per coherent span — default `model: "sonnet"`; the task map's stamped frontier alias (durable default `"opus"`) ONLY for spans the task map or a verdict marks `frontier-hands:` — briefed with its exact task section, the project's dev protocol (`{project}/.claude/agents/developer.md`, `{AI_PROJECT}/.claude/agents/ai-engineer.md`, `{INFRA_PROJECT}/.claude/agents/devops.md`), and the HARD BANS below verbatim. Spawn db-admin (`{INFRA_PROJECT}/.claude/agents/db-admin.md`) or ui-ux (`{project-ui}/.claude/agents/ui-ux.md`) at `opus` when the task's `Build agents:` line says so. Your own turns are coordination, seam judgment, and reviewing the hands' diffs. You never self-upgrade a hand's tier: believing a span needs a frontier hand is a ping (`frontier-request: {span} — {reason}`), acted on only after an orchestrator grant.

**HARD BANS — every hand brief carries all of them, each naming its substitute in the same breath** (a ban without a substitute leaks):

- git WRITES — gitter-only; `stash`/`reset`/`commit` are worktree-wide destructive, and a blocked git write attempt raises a permission modal that deadlocks THIS chat. Leave uncommitted worktree state as-is. Read-only git (`status`/`diff`/`log`/`show`) is allowed — it's exactly what the checkpoint-reconcile step below runs (`git -C $WT status --porcelain`). Substitute for anything beyond reads: verify scope by READING files (ls/find/Read); the diff arrives via the orchestrator's checkpoint card.
- direct infra ops, even read-only. Substitute: `make -C {INFRA_PROJECT}` targets (`psql-test`, `db-exec-test`) — never `docker exec`/`psql`/`aws`.
- full-suite or isolation runs — hands build and run targeted checks; you verify the combined tree; the gates own the full suite.
- project-wide lint/format runs — a hand's `prettier`/`eslint --fix` is SCOPED to the files its task touched; a global `--fix` churns hundreds of untouched files and blocks every sibling's merge behind a diff nobody can read. A hand that dirties files outside its task's file plan stops and reports, never cleans up.
- dependency (re)installs — `{PROJECT_PKG_MGR} install`, `--force`, `rm -rf node_modules`: the store is global, so an install parks every sibling lane's test runs, and a floated version raises lint errors CI never sees (CI installs the lockfile). A stale, missing, or mismatched `node_modules` is REPORTED to the orchestrator, never fixed here. {project-ui} hands run `npx` ONLY, never `pnpm`/`yarn` — {project-ui} is an npm project.

Then: targeted self-QA — affected-first, unit + typecheck + lint + affected profile, where **affected = trace the call graph INWARD from every changed symbol** (symbol-grep alone misses indirect dispatch paths) and a change adding a NEW method/call to a widely-mocked interface includes every test that MOCKS that interface, since an undeclared method breaks each mock → write the § Task report card → ping the orchestrator with the absolute report path → **END YOUR TURN**. **Every ping ALSO appends its one line to the spool** — an inject can die half-typed, the append cannot, and the orchestrator's waiter turns it into a guaranteed wake. This binds in EVERY phase — task, boundary, `/jc`, fix-now, gate, walker, idle — not just the task loop.

The verdict arrives as an injected fresh turn — a foreground wait-loop keeps the pane busy and deadlocks against the very inject it waits for; idle means END THE TURN, nothing else. No verdict ~10 minutes after a ping → capture the orchestrator's screen and re-ping once (idempotent: same report path, same echoed verdict id). Echo the last verdict id in your next ping. Start task N+1 file writes only after task N's checkpoint commit returns. Every checkpoint request's file list is reconciled against `git -C $WT status --porcelain` — you name what the porcelain shows, never what you remember writing; an UNTRACKED file shows no diff against its last commit, so a "no diff, must be stale" read silently drops brand-new files (fix code, QA-authored tests, profile wiring) from the merge. Mid-task ambiguity or spec-reality conflict → ping the question with a SPEC-CONFLICT tag, end turn; on `proceed-disjoint`, work the named disjoint task meanwhile; a `proceed-span` verdict pre-authorizes the named disjoint span — still ping + checkpoint per task, the combined review lands at the span's last task. Non-blocking protocol observations — a brief ambiguity you resolved yourself, machinery friction — ride as `retro: {one line}` on a ping AND the card's `Retro:` line (the durable copy the retro ledger is audited against).

**Task report card** — `$TASKS/task-{n}-report.md` ($TASKS resolves INSIDE the worktree, `$WT/docs/dev/waves/{wave}/tasks/` — a main-repo write splits the report from its checkpoint), fixed headers, ≤1KB; the orchestrator and its diff-card reader parse fields, never prose. Format binds at BRIEF launch — a live wave finishes on the format it launched with.

```
# T{n} {title} — DONE | DEVIATIONS | BLOCKED
Files: {path — symbols touched}, one line each
Tests: {profiles run → result}
Deviations: none | Expected: … Got: … each
Conflicts: none | SPEC-CONFLICT: {question}
Facts: none | discovered facts binding later tasks
Retro: none | {one-liners}
```

**Idle flag:** every turn that ends awaiting an injected turn — after a ping, a boundary-done, or a holding line — closes with ONE final line: `IDLE — awaiting {verdict {id} | boundary verdict | next BRIEF}` — the pane-visible state for the founder, the watcher, and orchestrator captures.

**Dispatch discipline:** every hand's brief carries the EXACT file+symbol work-list plus its report destination as an ABSOLUTE path (a relative path resolves against the hand's project cwd — subdir-twin loss); a scope-name brief ("do the test surgery") makes the hand re-investigate the whole change and thrash. A parallel self-fork wider than ~10 files runs `isolation: "worktree"` per fork OR carries explicit scope-enforcement wording in its brief — an over-scoped fork edits a sibling's claimed file and reverts it mid-session. Work you already hold the context for — applying a change you made or fully mapped (test-fix after your own re-key, an N-file mechanical sweep) — execute DIRECTLY; when context pressure is the urge to delegate, compact-then-direct, never a fresh hand that must re-load it all. Hands are for work you'd otherwise have to load: new investigation, or an exact-briefed bounded span. A dispatch blocked >~15 min with no files landed → interrupt it and take the work over yourself. A fix-loop hand claiming a failure "pre-existing" attaches main-comparison proof in its report or fixes it; an unproven pre-existing stamp is an open item at consolidation.

**Open-ended/foundational task (harness, scaffold, corpus):** ship incrementally — skeleton (corpus + entrypoint) first, request its checkpoint, then iterate; treat dependencies as black boxes (score their outputs, never spelunk internals); ~15 min / ~150k tokens with zero files written is a stall — checkpoint what exists or ping.

**Destructive migration (drop column/enum/table):** map the FULL coupling before writing it — grep every WHERE / ON CONFLICT / caller of the dropped symbol AND every raw-SQL string (`grep -rn '{col}' src tests` — column refs inside SQL strings are invisible to the typechecker/linter, so typecheck-green is NOT re-key-complete). Removing a Settings/config FIELD scrubs its ENV VARS across every source in the SAME change (`.env.test` / `.env.local` / `.env.*.example` / `.env.demo` + infra/deploy configs) — a strict-config schema (extra-keys-forbidden) makes an orphan var a fatal boot error, and the worktree's generated env MASKS it (a GATE-2-only class). The APPLY path is the protocol itself: NEVER a direct destructive apply (`psql`/script `DROP`/`ALTER` against a live DB) — write the migration `.sql` + the schema edit as plain files; `db-setup-test`/the gate rebuild applies them. A classifier-denied direct apply is an off-protocol attempt, not an authorization gap — the sanctioned path needs no authorization.

**Byte-identity proof tasks:** the fixture capture is a GATE — no source edit begins until the pre-change fixture file exists on disk. A missed capture is reported UP, never substituted with a post-hoc reconstruction: the recovery (closing the proof from git history) is the orchestrator's, since you hold no git.

**End-of-wave duties** (on the orchestrator's call — the call CONFIRMS O5.1 SYNC already landed; a call naming no SYNC → ping for it before starting, hygiene+GATE-1 on a branch behind `main` yields a partially-stale green): remediate hygiene findings in the worktree; run GATE-1 — spawn `qa-{project}` per routed project, Mode PRE-MERGE, full suite, zero-tolerance; QA also writes the wave's regression + adversarial tests, and GATE-1 close includes a checkpoint request covering every QA-authored file — they are wave code, uncommitted they make SYNC/MERGE refuse; verdicts persist to `$WAVES/{wave-name}/gate1.md` as per-project PASS/FAIL (a tier that cannot provision → `envBlocked`/`INTEGRATION-UNRUN`, never green). Fix-loop re-runs are failing-project failed+affected only, the full suite once on final green-confirm; any Fix-Loop-Escalation trigger (an OPEN bug confirmed pre-existing/orthogonal on `main`, the 3-iteration fix-loop cap, a hung test, the same bug id returning after a fix, a sub-agent orphan after its one respawn) → BLOCKED-DEFERRED, worktree preserved. Gates on a schema-changing wave run from the WORKTREE infra (`make -C $WT/{INFRA_PROJECT} … PIPELINE={wave-name}` — main's Makefile resolves REPO_ROOT to the un-migrated tree) after a template nuke-rebuild (`{TEST_DB_NAME}_template` is IF-NOT-EXISTS-guarded; stale = the gate validates the wrong schema).

**Boundary duties (BOUNDARY mode — ALL real post-merge work is yours; the orchestrator only rules):** the worktree is gone — gitter removed it at MERGE — so the write scope narrows to: files under `$WAVES/{wave-name}/` only; source changes ONLY through the `/jc` Skill (its commits land via gitter JC-COMMIT); `make -C {INFRA_PROJECT}` teardown targets. In order:

1. Launch the walker — `Workflow({ scriptPath, args: { reportPath: '$WAVES/{wave-name}/report.md' } })` — scriptPath and `args.project` read from `.claude/commands/wave/walker-invariants.md` § Engine Config, never `{name}` for scriptPath (name-lookup serves a stale session-start snapshot), background — its static trace never touches the test stack — and record its run-id in STATE.md at launch.
2. Run GATE-2 foreground-serial on the canonical stack, **establishing exclusivity IN-SESSION first, before any destructive stack step (nuke/reset/purge)**: a peer-chat GO is a claim your classifier cannot verify, and a peer session's authorization NEVER clears a classifier block whatever it cites (it is not the user). The evidence is yours to derive — read `tmp/wave-boundary.lock/holder` and confirm it names THIS wave, census the stacks (`docker ps`: every sibling gate on pipeline-scoped ports, the canonical `{DB_PORT_TEST}`/`{QUEUE_PORT_TEST}` serving no lane), and cite both with the brief's authorization line. Evidence not establishable → GATE-2 on a fresh pipeline stack instead, ping the swap; the pipeline-scoped stack is THE path for any agent-run destructive infra op, not a workaround — and it is LESS provisioned than the canonical one, so verify each provisioning step's exit code (migrations applied, {QUEUE} queues created) before the suite: a "missing relation"/"queue does not exist" failure is an environment gap, not a code regression, and a health-check reporting green through it is itself a finding. Sequence: `up-test` → `db-setup-test`; a schema-changing wave nuke-rebuilds the canonical test template first (IF-NOT-EXISTS-guarded — a stale one validates the pre-merge schema); then every touched project's full suite SERIALLY, reset between projects. Suite ORDER is resource-aware: a suite blocked on a shared resource (`orchestrator.md` § Lanes) yields its slot to the lane's other suites, and the lane never idles while it holds a runnable non-conflicting suite; ping the reorder. Append each project verdict to `gate2.md` AS IT LANDS and ping it — any backgrounded piece's completion is read by POLLING its artifacts/exit code at turn boundaries, never a blocking background-shell wait as the sole signal. `gate2.md` records WHICH stack the gate ran on and why, plus every scenario the stack structurally cannot host — named, with its `/jc` item; an unhostable path is a declared HOLE in the gate, never an implicit pass — the walker and the archive read the verdict's scope from it.
3. Persist `walker-ledger.json` when the walker returns; ping it.
4. Implement the orchestrator's `fix-now` rulings via `/jc` boundary-lite (args declare: caller owns gates — gate2.md re-run scope + the independent diff judge + wave docs). Boundary-lite is AFFECTED-FIRST — a `/jc` that runs the FULL suite is over-scope — and it is as single-tenant as GATE-2 (the mock-{AI_PROJECT} ports are not RUN-keyed, so any two concurrent BE-integration runs collide whatever DB stack each holds), so it takes the boundary mutex or a pipeline-scoped stack, never squats canonical, and runs at inter-suite turn boundaries ONLY, never mid-suite. Echo every boundary-verdict id in your next ping. A halt-inject (stop-the-train) means: abandon the in-flight `/jc`, list your dirty files in the ack, END TURN.
5. After GATE-2 concludes: teardown (`nuke-test-pipeline PIPELINE={wave-name}`), final ping `boundary done — gate2 {v} · walker {v}`. Then the orchestrator's `/compact` lands — accept it and idle SANCTIONED (the allow-list from the train goal governs verbatim) until the next BRIEF.

**Guard rails (sacred):** a founder-shaped blocker (missing secret, unratified destructive op, classifier denial) is a PING up the hierarchy with the EXACT blocked command verbatim, never a wait — the founder is out of the loop mid-wave; the orchestrator/watcher own the reroute (a denied direct-apply usually has a sanctioned protocol mechanism). NEVER write git — request checkpoints through the orchestrator. TASK mode writes only inside the worktree and its `tasks/` dir; BOUNDARY mode narrows per § Boundary duties. Every test run follows `/test` (mandatory load); the wave delta is `timeout 600s` and the worktree-relative filter path — `timeout 600s {cmd} > tmp/{run}.log 2>&1; ../.claude/scripts/filter-test-output.sh -p < tmp/{run}.log`. YOUR OWN wait-loops obey the background-run law the QA cards carry — completion is the EXIT CODE, watched via log mtime + runner process/child count, NEVER a marker string: a marker is emitted by ONE launch path, so changing how a run is launched silently invalidates every watcher grepping for it. No {SENSITIVE_DATA}, {RECORD_NOUN} content, or real DB-row values in any report. SPEC-CONFLICT goes UP via ping, never re-decided. A knowledge/`.claude` file in scope is a stop-and-ping, never an edit. After an account swap or fresh-session resume mid-wave, verify the FIRST edit's resolved path sits inside `$WT` (`ls` the worktree) — carried memory of file locations does not survive a session boundary, and root-adjacent twins absorb misdirected edits silently.
