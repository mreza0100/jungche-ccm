## Pending

- C: pfm — the live cosmos never shows a dead or hidden chat: `BuildCosmos(..., live=true)` now drops every node whose chat is Killed or whose unmatched identity has aged past its grace window (and every edge naming one) before the graph is ever returned, so a killed or hidden chat gets no blink, no fade, no debris in the sky — a node the picker would not list is not in the graph. The chronoscope replay is unchanged: a chat dead now still renders dimmed as the ghost it was, and `enter` on it reads "enter needs a live chat — {label} is gone; only the ledger remembers it". The two death-animation constants and the model's death-window bookkeeping (`cosmosDiedAtNS`, `cosmosDeathVisual`) are removed along with the behaviour they animated; `CosmosRowGrace` replaces `CosmosDeathBlink`+`CosmosDeathFade` as the one grace window an unmatched identity gets before absence means gone.
- A: pfm — `pfm chat reload --fresh --hide` hides the conversation a fresh reboot leaves behind: once the reboot has completed (never before — a reload that fails leaves the live chat listed), a permanent kill is recorded for the old id through the same manager as `pfm chat kill`, so the picker stops listing it as resumable; `pfm chat unkill <id>` brings it back. `--hide` needs `--fresh` (a reload that resumes the same conversation cannot hide it) and rides the `/reload` intercept hook like every other flag; the `/reload` description and card teach it. `/handoff` now passes `--fresh --hide`, so the chat handing off is retired from the picker the moment its successor owns the pane.
- A: pfm — `pfm chat reload` no longer strands a chat behind its own `/exit`: the worker holds the `/exit` until the calling chat's turn has ended (up to two minutes, then refuses without typing; `PFM_RELOAD_IDLE_TRIES`), presses Enter on Claude Code's "background work is running" exit dialog — the modal a chat with a session cron or background shell answers `/exit` with, which the old worker never confirmed and left open, holding every queued prompt behind it for hours — and when the chat still will not exit it takes back what it put on screen (dismisses the dialog, or backspaces the typed `/exit`) and names that state in the log instead of a bare "chat left running".
- A: pfm — `chat_self_compact` takes exactly ONE steer (`then` is a string, never a list) and its description is the exclusive answer to "compact yourself" — this tool and nothing else, never a hand-typed `/compact`, never a reboot of the pane — and says the session survives a compact (crons, sub-agents, pane). The `/reload` card drops the never-implemented "force-killed after 20s" claim for what the worker actually does. The fleet prompt gains the milestone rule: durable state to its file, then one self-compact with one steer, end the turn — `/handoff` and `/reload` are the user's commands, never run without the user's permission.
- A: pfm — a milestone self-compact reminder, config-gated: `pfm internal compact-nudge` (global `UserPromptSubmit` hook, Claude only, main chat only — sub-agent turns are skipped) reads the context percentage the statusline now persists per session from Claude Code's own `used_percentage`, and when the chat climbs into a new band (`start`, `start+step`, …) injects ONE reminder that IF a milestone is here, this is the moment to write durable state and `chat_self_compact` with one focus line and ONE steer — worded as a reminder, never an order; once per band per climb, re-armed after a compaction. Policy in `claude.compactNudge {enabled, start, step}` (defaults `true/35/10`, per-account override, shown by `pfm config show`).
#### → For: `pfm install --yes` wires the new hook; running chats pick it up on their next prompt (cost: one hook process per prompt, one small file write per statusline render).
- A: pfm — `/handoff` and `/reload` descriptions open with USER-ONLY — "never run this without the user's permission"; their bodies carry mechanics only, and neither names the other or the compact tool; `chat_self_compact`'s description and the MCP instructions name no slash command at all; the `/reload` card's limit-rescue section and the README describe a move the user asked for, never a self-serve swap.
- A: pfm — the statusline's cache timer anchors on the last API request, not the last user-typed record: a local slash command (`/rc`, `/cost`, the `/compact` receipt) writes user records without touching the API, and the old anchor made a cache cold for twelve hours read "💾1h✗9m". The anchor is now the newest main-chain assistant record or non-local-command user record.
- A: pfm — Stats tab token counts stop over-counting: Claude writes one transcript record per content block of an assistant message, each repeating the message's `usage`, and the sampler summed every record — a live transcript measured 2.49× inflation in the lifetime tokens column and therefore in tokens/min. Usage is now counted once per message (`message.id`, falling back to `requestId`); records without either still count individually.
