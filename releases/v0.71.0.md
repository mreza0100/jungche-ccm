# v0.71.0 — 2026-09-07

Breaking release. Professor's legacy `cc*` shell surface is retired: a fresh Claude chat is synthesized in Go by `action.ClaudeSpawn` instead of calling a user shell function, every retired regular file is backed up before removal, and symlink targets are left intact so an unrelated command sharing a retired name survives. `/p:360` is gone end to end — its QA sweep replaced by a closed-world diff-driven attack map, and `/rnd`'s blind-spot sweep now carries its dimensions inline rather than pointing at a deleted file. The interactive picker renders in color by default while learning a distinction it never made: a shell that asked for no color is a preference and is overridden, a terminal that says it cannot render SGR escapes is a capability and never is.

Six gates that could report the wrong thing about their own health were corrected. A leak check called a change clean having scanned 1 of its 7 published files. A test gate accepted a cached package as a watched run and gave the suite ten minutes when one stress test alone needs four and a half. A manifest gate was unsatisfiable for the length of any deletion. A tracked mirror link resolved in exactly one working copy and in no clone. In each case the gate answered the same way when healthy and when broken, which is the one failure a gate must not have.

## Breaking

- Major: shell launch surface (cost) — Professor's `cc*` shell commands, aliases, launch/account helpers and the `pfm internal prompt-args` dispatcher are retired. A fresh Claude chat is synthesized in Go by `action.ClaudeSpawn` — account, prompt, cache and permission settings preserved — instead of calling a user shell function; only a Codex row still calls `cx`. Retired regular files are backed up under `~/.local/state/pfm/retired-commands/` before removal and symlink targets are retained, so unrelated commands sharing a retired name survive (the system C compiler and `ccache` are untouched). The managed VS Code terminal profile moves to `PFM_AUTO_OPEN=pfm` while user-edited profiles are preserved, and a legacy auto-open selector falls back to the picker rather than invoking a retired command. `promptFile` fails OPEN when the staged professor prompt is missing — the `--system-prompt-file` flag is omitted and the chat opens lean, which is the retired shim's own contract — with `pfm doctor`'s spawn audit as the surface that reports the gap.
  #### → For: run `pfm install --yes`, then open a new shell or source the refreshed shim. Use `pfm` and `pfm chat open <target>`; accounts are chosen in the picker. Removed regular command files are recoverable under `~/.local/state/pfm/retired-commands/`. (cost: the managed terminal profile's environment changes from `CC_AUTO_OPEN` to `PFM_AUTO_OPEN`.)

## Removed

- Removed: `/p:360` — the 360° sweep command is retired end to end, with every citer rewritten rather than left pointing at a deleted file: `templates/project/commands/p/360.md` deleted, the "spawn a clean-context 360 sweep" paragraph removed from `audit/{code-hygiene,security,ai-output}.md` and from `pm.md`'s pre-flight list, and the `qa-commons.md` § 360° sweep section replaced by § **Diff-driven attack map** — walk the change delta hunk by hunk, one line per hunk carrying either an attack hypothesis or an explicit no-attack justification, closed-world so a hunk absent from the map is uncovered rather than implicitly safe. `per-project/qa.md` Step 3.5 follows that section instead. `/rnd` keeps its blind-spot sweep but now carries the dimension list inline (inputs and boundaries, state and concurrency, failure and recovery, scale and performance, security and trust, integration and contracts, observability, unstated assumptions) rather than delegating to a file that no longer exists. Pointers cleared from `BLUEPRINT.md` (×3), `README.md`, `SETUP.md` (prose + parameterization table), `skills/sources.json`, and `refresh-map.json`; `{SECONDARY_PERSONA}` loses its only consumer and no longer appears anywhere in the tree.
  #### → For: installs carrying `/p:360` delete `.claude/commands/p/360.md` and re-pull `audit/*`, `pm.md`, `rnd`, `per-project/qa.md` and `qa-commons.md`; a QA seat that ran the 360 sweep runs the diff-driven attack map in its place.

## Changed

- Minor: interactive picker — the picker renders in color by default even when a parent shell exports `NO_COLOR=1` or `CLICOLOR=0`; `pfm ls --plain` and `--tsv` stay uncolored. The decision separates capability from preference: those two variables are a shell PREFERENCE and are overridden by design, while `TERM` unset or `TERM=dumb` is the terminal stating it cannot render SGR escapes and is never overridden — forcing color there writes escape bytes into a screen that cannot show them. The profile is computed from an explicit environ slice, so nothing ambient reaches it — notably the process's own `TMUX`, which `colorprofile.Detect` resolves by shelling out to `tmux info`, and which had been deciding a profile the tests attributed to `TERM`.
- Minor: memory helpers (cost) — `cc-memory-wire.sh` and `cc-memory-consolidate.sh` ship as `memory-wire.sh` and `memory-consolidate.sh`. `pfm install` migrates recognized installed copies and exact hook references without running the helpers or touching memory data, backing up every settings file it rewrites; a customized copy, an ambiguous hook command, or an unsafe settings target is refused rather than overwritten.
  #### → For: after `pfm install`, the `SessionStart` hook points at `memory-wire.sh`; a hand-customized copy is deliberately left alone and is renamed by hand.
- Docs: pfm/CLAUDE.md — records that pfm targets Linux and Darwin from one codebase, and adds § Platforms: the gated-dependency table plus the two rules a platform gate must satisfy — a fallback's gate covers every platform that reaches it, and `VersionArgs` are safe only when every gated platform's build accepts them.

## Fixed

- Patch: pfm install (cost) — a dangling global-command link no longer aborts the install that exists to prune it. An apply run opens with a dry-run preflight, and only a dry run stages the command tree to preview the Codex plan; v0.70.0 retiring the `p/` namespace left every v0.69.1 host with a dangling `~/.claude/commands/p`, and `copyPlanTree` returned `EvalSymlinks`' error before `retireOrphanGlobalCommands` could ever run. The tree could not self-heal — every subsequent install failed identically, blocking the v0.69.1 → v0.70.0 upgrade outright. Preview now steps over any unresolvable link (only `ErrNotExist`; every other error still fails honestly), replacing a name-list of retired commands that had to be extended for each future retirement and had already missed `p`.
  #### → For: adopters stuck on the preflight error re-run `pfm update`; no manual link removal is needed.
- Patch: pfm deps (cost) — `nohup` resolves on darwin, so the `setsid` detach fallback can engage. `setsid` ships with util-linux and is absent on darwin, making darwin the ONLY platform that ever reaches that fallback — but the registry gated `nohup` to linux, and `deps.Resolve` refuses a gated name off-platform before `exec.LookPath` runs, so pfm refused `/usr/bin/nohup` on every macOS. That disabled `chat_self_compact` and every other `--then` waiter there. `VersionArgs` is dropped as the gate widens: BSD `nohup` rejects `--version`, which the probe reports as a broken binary, and presence is the only fact a non-required entry needs.
- Patch: tokens — the Claude PRICING rows carry the published rates instead of tier guesses: Opus 4.5 and newer are 5/25 (4.1 and 4.0 stay 15/75), Sonnet 5 is 2/10 as a permanent rate rather than the cancelled 2026-09-01 step-up, Haiku 4.5 is 1/5, and Fable/Mythos are 10/50 rather than Sonnet-class. Rows are ordered most-specific-first, because the lookup takes the first substring hit on the lowercased model id. Codex rows untouched.
- Patch: tokens — the `opus-4-0` PRICING row is replaced by `opus-4-20`, and a new `scripts/check-token-pricing.mjs` gate resolves every published model id against the table. PRICING matches by first substring hit on the lowercased id, and Opus 4.0's id carries no minor digit (`claude-opus-4-<date>`), so the literal `opus-4-0` matched nothing and every Opus 4.0 transcript fell through to the 5/25 catch-all — a 3x undercount that reading the table could not reveal, only resolving it could. The gate is wired into the templates suite and reports `PRICING-UNREADABLE` (exit 2) when it cannot find or parse the table, so "every rate as intended" and "the table could not be read" never print the same.
- Patch: scripts/check-codex-markers.mjs — a tracked path that is not a regular file (a symlink to a directory) is NAMED as not-scannable and excluded, instead of failing as an unreadable regular file. It carries no marker header and never could, so it is outside the gate's domain rather than something the gate failed to read; failing on it made the verdict depend on whether the link happened to materialize — deleted in one checkout it warned and passed, present in another it failed, on identical content.
- Patch: scripts/check-codex-markers.mjs — the gate now reconciles every tracked SYMLINK against its target, not just every marker against its source. A tracked link is a promise that its target arrives with the clone, and whole mirror trees here are ignored by design (`.claude/skills/`, `.opencode/skills/` — source-fetched, regenerated by `pfm codex build`), so a tracked link into one of them resolves only in the working copy that added it. Two states are named: `DANGLING-LINK` (no target on this disk) and `UNTRACKED-TARGET` (target inside the repo but untracked). Before this, such a link surfaced as whatever gate walked the tree first said — "unreadable", `EISDIR`, a dangling-source warning — never as the broken promise it was, and the summary line now carries the count of links verified so a clean run states what it checked.
- Patch: infra/check-self-hosted-manifest.sh — an empty `ROOT` argument exits 2 with `NO-ROOT` and its usage line instead of reporting `missing ` and `missing /VERSION`: paths nobody asked about, which read as a broken install rather than as a call made with no argument. "Nothing was verified" and "verified, and the ledger is stale" are now different exits (2 vs 1).
- Patch: scripts/leak-check.sh — a clean verdict from the `staged` and `range` modes now names the coverage that earned it (`clean — N added line(s) across M file(s) scanned against T private term(s) + 3 structural pattern(s)`), and a diff with no added lines prints `NOTHING TO SCAN` instead of the word clean, still exiting 0 so a pure-deletion push passes. Only the `--files` mode counted its work before this, which is the coincidence-detector shape the script's own header forbids: a run over an almost-empty index printed exactly what a full-tree scan printed. Because the scan runs as the last stage of a pipeline — a subshell whose variables never reach the parent — the counts travel through a coverage file, and a coverage file that is missing or unparseable FAILS the gate rather than defaulting silently to zero. An added line arriving with no `+++` header is counted separately and named in the verdict, never folded into the file count.
- Patch: agents/gitter — § Scoped-commit discipline gains the index-only rule: `git commit -- <paths>` takes the WORKING TREE for those paths, so a staged `git rm --cached` of a file still on disk is silently re-added and the commit contradicts its own message. Such a change is staged alone, verified with `git diff --cached --name-status`, and committed from the index with no pathspec. The pathspec rule for ordinary content commits is unchanged, and it now states the flag order it depends on: options and the message flag go BEFORE the `--`, because everything after `--` is a pathspec and an `-m`/`-F` placed there is read as a filename.
- Patch: infra/check-self-hosted-manifest.sh — a tracked path missing from disk now reports `TRACKED-DELETED` (a deletion awaiting its commit) instead of `NOT-HASHABLE` (a path that is not a regular file, such as a symlink to a directory); both are excluded from coverage, neither is silent, and they no longer print the same line. The `installed.{agents,commands,scripts,output_styles}` roster check derives from tracked paths that EXIST, matching the `file_hashes` coverage rule directly above it — before this, a file deleted but not yet committed was still demanded of the manifest as "installed", which made the gate unsatisfiable for the length of a deletion.
- Patch: dev.sh templates gate — the leak step scans the WHOLE changed working tree, not a `templates scripts README INSTALL CHANGELOG releases` pathspec. Every tracked file in this repo is published, so a change touching `docs/`, `.claude/`, `.codex/`, `.professor/` or `infra/` used to print `leak-check clean (N changed file(s))` having scanned none of it — and the count made the claim look earned (a 7-file change reported 1). Deleted paths are dropped and counted rather than handed to `--files`, which correctly refuses to call a list of non-files clean; an all-deletions change says so outright, and the no-changes fallback now states that its full scan covers `templates/` + README + INSTALL and NOT the whole repo.
- Patch: dev.sh pfm gate — `go test ./...` runs with `-count=1` and a measured `-timeout 25m`. Without `-count=1` a package whose inputs are unchanged reports `ok (cached)` and the gate called a run it never watched a pass — the same trap the testing law names, sitting in the gate that enforces it. The timeout is measured rather than guessed: `internal/index`'s OpenCode WAL stress test alone takes ~4.5 minutes (268s watched, passing), so Go's 10m default turned an ordinary loaded host into a red suite that named the wrong cause — a package-level timeout panic reports whichever goroutine held the clock, not the test that spent the budget.
