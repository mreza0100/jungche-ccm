# v0.57.0 — 2026-08-17

## Added

- Framework: quality/prompt.md § Anti-patterns — four new cut-on-sight classes from the opus-era infrastructure audit: self-verification rituals (frontier models self-verify; independent reviewers exempt), recall muzzles ("only report high-severity" measurably suppresses findings), weaker-model scaffolding (repetition/force-markers/undated model-behavior claims tuned to an older generation), and fabricated context (fake user quotes as forcing devices).
- Framework: wave/refine.md — new **R2.4 reviewer gate** (the founder picks which of three reviewer slots run — PM at R2.5, officer at R2.6, PM at R3.5 — each offered with what it would catch on this wave's shape; architect at R3.5 runs unconditionally on every wave, outside the gate) and **R2.7 facts reconciliation** (always-on, gate-independent: diff every settled decision against the facts registry for facts the wave invalidates / outgrows / newly pins, surfaced as its own dialog since facts change on an explicit ruling alone, the approved edit written by the main loop post-merge). The three contradicting "mandatory" statements reconciled, and the completion report now distinguishes `not run` from zero findings on the two gated PM slots and officer — architect always reports counts. R2.7 exists because the facts check had been a side effect of the officer review running; gating that review would have deleted it silently.
- Framework: new **`architect` agent** (opus, xhigh, read-only tool list) — adversarial pre-build design reviewer, lifted out of wave/refine.md R3.5's inline brief, which now calls it by type. Encodes the review laws the inline brief lacked: verify every claim against the code rather than the document's own anchors; check that a claimed enforcement mechanism covers what it is credited with (a `tsconfig` exclude silently voided a "the compiler enumerates every call site" premise); hunt hardcoded literal lists shadowing a derived constant (one in a JWT payload validator would have locked the platform owner out of production, invisible to `tsc`); treat producer/consumer pairs as coupled edits rather than a flat list; verify each partition can merge alone with green gates; count the counts; and close with an anchor-drift table plus a confirmed-correct coverage declaration so silence has a defined meaning. The read-only tool list enforces "review only" mechanically instead of by instruction.
- Framework: **every project agent is now registered at root** on the `{role}-{proj}` convention — 11 new wrappers joining the six `qa-{proj}`: `developer-{be,fe,web}`, `ai-engineer-cortex`, `devops-infra`, `author-contracts`, `db-admin-be`, `ui-ux-fe`, `{researcher,reviewer,seo,writer}-web`. An unregistered child file is spawnable only as `general-purpose` reading a path, so its frontmatter — model tier, tool allowlist, hooks — never loads; the wrapper is what makes those real. Wrappers stay thin registration shells over a child-protocol pointer, except web's, which inline the protocol because its child repo is contractor-visible. Renames: `contractor` → `author` (the name stuttered against its own project), `web-developer` → `developer-web`. Spawn sites in `/contentor`, `/wave:builder`, and `/wave:orchestrator` re-pointed to the registered types.
- Major: p/tokens — the token ledger now covers BOTH harnesses. `--codex` attributes OpenAI Codex CLI spend per session thread from `~/.codex/sessions/**/rollout-*.jsonl` (+ `archived_sessions/`), with `--since <YYYY-MM-DD>`, `--by-day`, `--top <n>`, project scoping off the rollout's cwd, and per-subagent labels off `agent_role` (a Codex subagent writes its own rollout, so per-session rows ARE per-subagent attribution). `--since` also lands in Claude mode. The counting rule is the whole problem: `total_token_usage` is cumulative but RESETS on resume/compaction, so the tool sums each segment's PEAK — one 110 MB rollout resets 3×, where reading only the final counter reports 384,439 instead of 538,898,717 (1400× undercount), while summing the per-turn deltas overcounts because duplicate events re-emit an identical cumulative. Codex bills cached input as a subset of input, so `PRICING` gained a 4th cached-rate column; a model with no row reports cost `n/a` with its tokens still counted, never a silent $0. Rollouts reach 110 MB of tool output, so the scanner reads 4 MB windows (64 KB overlap) and JSON-decodes only matching lines — 0.35 s vs 5.3 s per such file, byte-identical, ~12 s for a 3.1 GB corpus.
- Minor: wave/sentinel — failure-mode sweep added as audit piece 7: token burn (/p:tokens, Codex wait-poll scale), comms cadence (builder chatter breach with goal text quoted), structure drift (segment splits, interim merges, substitute gates, un-ruled reorders)

## Breaking

- Major: wave pipeline — the merge-gating walker moves PRE-merge. Sequence is now hygiene → GATE-1 → WALKER (branch mode against the merge candidate, § O5.5) → MERGE → GATE-2. A verdict able to return SHIPWRECK must precede the merge it condemns; blocking findings are fixed in the WORKTREE via `/jc` and the worktree survives until the walker clears. GATE-2 remains post-merge as the regression check on `main`.
- Major: wave pipeline — walker ownership is SEAT-conditional, not dialect-conditional-on-the-builder. A Claude seat runs the Workflow itself; a Codex seat holds no Workflow tool, so it pings the WATCHER at `tmp/wave-sensor/watcher.handle` with the wave name and merge-candidate SHA, and the watcher runs the engine and returns the verdict plus artifact paths. Running the walk on request is now a named watcher duty (§ 2b) — its single execution exception to advice-only; the VERDICT stays the orchestrator's to rule.
- Major: wave pipeline — a hand-orchestrated walker fan-out is banned as a substitute for the engine. Absent the Workflow the wave BLOCKS on the watcher ping rather than degrading: a manual fallback skips the mop-up loop and self-reconciles its own file inventory, so it blesses exactly the defects the walk exists to catch.
- Minor: wave pipeline — the tracer is scoped as a READING instrument. A tracer/fast-mode consumer map is evidence for the walker and for review; it never gates, never verifies a wave, and never authorises a merge. The walker is the defect instrument.
