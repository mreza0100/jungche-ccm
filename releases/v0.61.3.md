### LLM upgrade runbook

This is the complete execution contract for an LLM upgrading Professor to v0.61.3. This corrective
release contains every v0.61.2 production feature plus the Darwin-safe update-picker verification
fixture. It does not change adopter blueprint files, configuration schema, MCP authentication, or
runtime behavior. Preserve unrelated work and never bypass a failed gate.

#### 1. Inventory the installation

1. In the Professor source clone and every checkout sharing its Git directory, run
   `git status --short`. Stop if the update clone is dirty; do not reset, delete, or silently stash
   another session's work.
2. Record the current machine state without printing credentials:

   ```bash
   command -v pfm
   pfm version
   pfm config validate
   pfm doctor
   pfm mcp ls
   ```

3. Exit every already-running PFM dashboard after installation. A live dashboard does not reload a
   replaced executable in place.

#### 2. Install the tagged release

Installations on v0.60.1 or later use the transactional updater:

```bash
pfm update --to v0.61.3
```

Require the candidate-build, reproducibility, install, doctor, and rollback receipts to name
v0.61.3. Stop if the source clone is dirty, the tag differs, candidate binaries differ, installation
fails, or doctor rejects the candidate.

For v0.60.0 or older, or when `pfm` is absent, bootstrap the official checksum-verified asset:

```bash
PFM_RELEASE_REPO=mreza0100/professor
PFM_RELEASE_TAG=v0.61.3

case "$(uname -s)" in
  Linux)  PFM_RELEASE_OS=linux ;;
  Darwin) PFM_RELEASE_OS=darwin ;;
  *) echo "unsupported operating system: $(uname -s)" >&2; exit 1 ;;
esac
case "$(uname -m)" in
  x86_64|amd64)  PFM_RELEASE_ARCH=amd64 ;;
  arm64|aarch64) PFM_RELEASE_ARCH=arm64 ;;
  *) echo "unsupported architecture: $(uname -m)" >&2; exit 1 ;;
esac

PFM_RELEASE_BINARY="pfm_${PFM_RELEASE_TAG}_${PFM_RELEASE_OS}_${PFM_RELEASE_ARCH}"
PFM_RELEASE_URL="https://github.com/${PFM_RELEASE_REPO}/releases/download/${PFM_RELEASE_TAG}"
PFM_RELEASE_TMP="$(mktemp -d)"
cd "$PFM_RELEASE_TMP"
curl -fLO "${PFM_RELEASE_URL}/${PFM_RELEASE_BINARY}"
curl -fLO "${PFM_RELEASE_URL}/SHA256SUMS"
awk -v file="$PFM_RELEASE_BINARY" '$2 == file' SHA256SUMS > "${PFM_RELEASE_BINARY}.sha256"
test -s "${PFM_RELEASE_BINARY}.sha256"
if command -v sha256sum >/dev/null 2>&1; then
  sha256sum -c "${PFM_RELEASE_BINARY}.sha256"
else
  shasum -a 256 -c "${PFM_RELEASE_BINARY}.sha256"
fi
mkdir -p "$HOME/.local/bin"
install -m 0755 "$PFM_RELEASE_BINARY" "$HOME/.local/bin/pfm"
hash -r
test "$(pfm version)" = "pfm v0.61.3"
```

Never install an asset with a missing or mismatched checksum.

#### 3. Reconcile and verify the host

Preview and apply the same concrete installer plan:

```bash
pfm install
pfm install --yes
test "$(pfm version)" = "pfm v0.61.3"
pfm config validate
pfm doctor
pfm mcp ls
pfm ls --tsv >/dev/null
```

Stop on a foreign-file conflict or any difference between preview and apply. Acceptance requires a
clean doctor, schema-2 configuration, readable enabled engines, loopback-only unauthenticated
Professor MCP routes, and successful fleet enumeration.

#### 4. Prove the v0.61.2 behavior remains intact

The complete Google Drive, in-frame Deactive, and next-invocation update-banner behavior is unchanged
from v0.61.2. Re-run the operator-facing proofs in the
[v0.61.2 runbook](v0.61.2.md#llm-upgrade-runbook) when upgrading from an older release or when any
of those surfaces is in doubt. In particular, a Drive receipt must name `pdf` and
`google-drive-download`, and Deactive must be tested only on a disposable chat.

At v0.61.3 while v0.61.3 is latest, no update banner is expected. A newer release is displayed only
after one invocation completes the silent lookup and the next interactive `pfm ls` consumes it.

#### 5. Require tagged CI and close the update

Verify the GitHub release is public and non-draft, contains four platform binaries plus
`SHA256SUMS`, and that every asset digest matches its checksum row. Require the Release, Installer
end-to-end verification, and Verify workflows triggered by the v0.61.3 release commit to finish
green. On Darwin, the update-picker E2E must create its tmux socket under the short isolated root;
`File name too long` is failure, never a platform skip.

Record the installed version, doctor output, installer summary, CI URLs, and final Git status. Do
not mutate the published tag, bypass checksums, or claim a network-dependent proof that did not run.
