# v0.56.0 — 2026-08-17

The engine was written on Ubuntu and had never run on a Mac. Porting it was supposed to be a day of
build tags. What the port actually found was a data-loss bug sitting in `main`, armed and waiting on
an `apt upgrade`.

`pfm ls` deleted the tmux sockets of five live, healthy chats. The servers kept running with their
transcripts; only the path every client and every `pfm` lookup reaches them by was gone, so each one
rendered as merely resumable — indistinguishable from a chat that ended. The cause was two faults
lining up. Five parsers split tmux's `-F` output on the literal text `\037`, but tmux 3.6 emits the
raw `0x1F` byte, so every chat became unparseable. And the sweep in `tmuxprobe.go` removed a socket
on *any* probe error rather than only on "no server here" — the `ErrServerGone` guard existed, but
was attached to the warning instead of to the deletion, one statement short.

Linux is not exempt. It is unsprung there only because tmux ≤3.5 escapes the separator, so the parse
succeeds and the sweep never fires. And the `>1h` age check that looks like a safety guard is the
opposite: "untouched for an hour" does not describe a dead chat, it describes a live idle one. The
victim class was the worst one available.

Both halves ship here, and each is insufficient alone. Alongside them, macOS becomes a real target
rather than a mostly-working one, from a single binary and a single source tree.

## Fixed

- Mechanics: `gather/tmuxprobe.go` — a socket is swept ONLY on `ErrServerGone`; every other probe error warns and leaves the socket alone. A probe that could not run never returns "nothing found", and it certainly never deletes the thing it failed to read.

  #### → For: if chats became resumable on tmux 3.6, the servers are usually still alive. Recover the socket name from the server's own argv with `ps -Ao pid=,command= | awk '/tmux -L (cc|cx)-/ {for(i=1;i<=NF;i++) if($i=="-L"){print $1, $(i+1); break}}'`, then `kill -USR1 <pid>` — tmux recreates the socket file. Sweep every chat pid before attaching anything; a `pfm ls` in between will not re-list them.

- Mechanics: `internal/tmuxfmt` — one parser for tmux `-F` output, accepting the separator as a raw `0x1F` byte or as the printable escape `\037`. All five parse sites route through it; five join sites already sent the raw byte, so send and receive are now symmetric.

  #### → For: this fix and the sweep fix are each insufficient alone. Parser-only leaves delete-on-any-error primed for the next unrelated tmux error; sweep-only leaves the fleet blind on tmux 3.6.

- Mechanics: the launcher shim strips `CLAUDE_CODE_CHILD_SESSION` on every launch, from one `CC_SESSION_UNSET` array shared by all three launch paths. A chat born inside another chat inherited the marker and ran with transcript saving silently OFF. (cost)

- Mechanics: the auto-open hook (`CC_AUTO_OPEN`) returns to the shim, deferred to the first prompt and disarmed before it launches. A terminal profile calling `cc` from `~/.zshrc` reached `/usr/bin/cc` — the C compiler — because the installer appends its source line to the BOTTOM. `pfm install` now reports any fleet command called above that line.

- Mechanics: two flakes that are not platform-specific — the branch jail read a detached seat's argv with a single `ReadFile` before the pane had exec'd, and a spawned `nohup` stub was given a one-second ceiling that only holds outside a parallel suite. Both now wait on the thing they are actually waiting for.

## Added

- Mechanics: `pfm` runs on macOS and Linux from one binary and one source tree. Where there is no `/proc` the process table comes from `sysctl` (`gather.NewProcFS`, `action`, `dream/seat`), and the open-gate ioctl is build-tagged per kernel. `gather.NewProcFS` still honours an EXISTING proc root, so the test jail keeps feeding fixtures unchanged.

- Mechanics: `pfm install` wires a launchd agent on macOS in place of the systemd units, carrying both triggers in one job — `WatchPaths` is the `.path` unit, `StartInterval` 900 is the `.timer`. Only the current platform's scheduler assets are staged, so neither host collects the other's dead files.

  #### → For: the rc 97 refusal narrows on macOS from "a user bus is reachable" to "the name-sync agent is mid-execution". There is no dead-launchd jail — launchd is always live for a logged-in user — so a literal port of the Linux gate would refuse every install forever. The two gates protect the same moment, not the same condition. A runner that cannot probe the gate makes the installer say the gate did not run rather than imply it passed. (cost)

## Changed

- Mechanics: `pfm doctor` reports `process_table readable pids=N` by READING the process table instead of stat-ing `/proc`. Better on Linux too: a `/proc` that exists and denies the read is the failure that matters, and a stat calls that healthy.

- Docs: `README.md` and `INSTALL.md` no longer describe macOS as mostly working, nor promise three systemd units and a dead-bus refusal on a host that has neither. `pfm/CLAUDE.md` records the two invariants the port introduced: the platform seam is a build tag rather than a runtime branch, and `internal/dream/*` may not import host packages — which is why the `kern.procargs2` decode is duplicated in `dream/seat` on purpose.
