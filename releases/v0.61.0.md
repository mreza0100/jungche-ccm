## Added

- Product: `pfm init [dir] [--force]` — scaffolds an adopter project from the recorded clone's
  `blueprint/` sources; force mode replaces stale Professor-owned scaffold paths.

## Fixed

- Fixed: `pfm harvest ask` — the documented command and `pfm harvest --ask` compatibility spelling
  now harvest up to 50 URL, identifier, or local sources into full cache artifacts, keep failed
  sources visible as temporary error receipts, and run the configured Claude or Codex model/effort
  adapter end to end.

- Fixed: host Codex reconciliation — `pfm install` and `pfm uninstall` now reconcile global
  Claude-command mirrors without compiling project files, deleting only marker-owned orphans and
  preserving unmarked conflicts and foreign prompt/skill files.

- Fixed: repository publication gate — `pfm doctor` distinguishes an armed pre-push hook from an
  existing-but-unwired or broken one, and the hook prints its effective `core.hooksPath` before the
  leak gate runs.

- Fixed: Harvester/update edge isolation — a first failed harvest creates its stats directory
  without a noisy append error, and self-update validates host health outside the invoking
  checkout so a repository-only pre-push warning cannot roll back a healthy binary.

- Fixed: cross-runtime agent registry — Codex and OpenCode now compile every Claude source agent,
  including the sole Git writer gitter, while all other roles remain Git-read-only and a roster
  parity gate fails on any future omission.

- Fixed: in-place reload — bare `/reload` keeps the current engine account, Codex app-server turns
  recover their tmux seat through the fleet-bound thread identity when `$TMUX` is absent, and the
  reboot confirms `/exit` rendered and was submitted before replacing the pane; `--then` recognizes
  both Claude and Codex composers before delivering its continuation, and state probes inspect only
  the visible pane so historical scrollback cannot trigger a reload action.

- Fixed: doctor SID metadata — completed reload logs are recognized as owned satellite metadata
  instead of inflating invalid-crumb warnings after every successful reboot.

## Changed

- Changed: retired integrations — the Vertex/gcloud statusline dependency and implicit spend rows
  are removed, while the isolated test fence now selects its real build architecture.

- Runtime: picker refresh cadence — an idle interactive picker backs off from five-second refreshes
  to five-minute refreshes until operator activity resumes.

- Runtime: OpenCode host command reconciliation — the compiler writes generated global commands to
  `~/.config/opencode/command` and removes only marker-owned orphans from that registry.

## Migration

- Migration: `v0.60.1` → `v0.61.0` — update the machine binary, re-run the host installer, rebuild
  every enabled project runtime mirror, and start a new or reloaded session so the refreshed agent
  registry is loaded. The configuration schema remains version 2; do not add credentials to the
  loopback Professor MCP routes.

#### → For: in a maintainer checkout, run `git config core.hooksPath .githooks`, then require

`pfm doctor` to report `pre-push gate=armed core.hooksPath=.githooks` before publication.

After updating, rebuild both runtime mirrors and start a new or reloaded session so the harness
discovers the refreshed agent registry.

### LLM upgrade runbook

This is the execution contract for any LLM updating an existing Professor installation. Read the
whole section before changing the machine or a project. The machine PFM lane and each project's
blueprint lane are independent: update only lanes that exist. Never discard local changes, expose
credentials, overwrite customized configuration, or edit generated mirrors merely to silence a
check. An unavailable probe is a named gap, never a pass.

#### 1. Inventory the installation and preserve local state

1. Detect the installed lanes:
   - Machine lane: `command -v pfm` succeeds.
   - Project lane: the project contains `.professor/manifest.json` and `.claude/`.
2. In every source clone and project repository involved, run `git status --short`. Classify all
   existing changes. Commit or stash only through that repository's authorized Git writer; never
   reset, delete, or overwrite another session's work.
3. Record the pre-upgrade machine state without printing secrets:

   ```bash
   pfm version
   pfm config validate
   pfm config show
   pfm doctor
   pfm mcp ls
   ```

   Preserve complete stderr for every failure. Do not print MCP headers, account tokens, or full
   credential-bearing configuration files.

4. Record the current project version from `.professor/manifest.json` and read every intervening
   release note. If the machine reports `v0.60.0` or older, also read the
   [v0.60.1 one-time updater repair](v0.60.1.md#llm-upgrade-runbook); do not run the affected old
   updater.

#### 2. Upgrade the machine PFM lane

For a machine already on `v0.60.1` or later, use the transactional updater:

```bash
pfm update --to v0.61.0
```

Read its build, install, doctor, and rollback receipts in full. Stop if the source clone is dirty,
either candidate build fails, install fails, or doctor rejects the candidate. Do not replace a
failed transaction with a moving-branch build.

For `v0.60.0` or earlier, or when no `pfm` binary exists, bootstrap the official asset directly:

```bash
PFM_RELEASE_REPO=mreza0100/professor
PFM_RELEASE_TAG=v0.61.0

case "$(uname -s)" in
  Linux)  PFM_RELEASE_OS=linux ;;
  Darwin) PFM_RELEASE_OS=darwin ;;
  *) echo "unsupported operating system: $(uname -s)" >&2; exit 1 ;;
esac
case "$(uname -m)" in
  x86_64|amd64)  PFM_RELEASE_ARCH=amd64 ;;
  arm64|aarch64) PFM_RELEASE_ARCH=arm64 ;;
  *) echo "unsupported architecture: $(uname -m)" >&2; exit 1 ;;
esac

PFM_RELEASE_BINARY="pfm_${PFM_RELEASE_TAG}_${PFM_RELEASE_OS}_${PFM_RELEASE_ARCH}"
PFM_RELEASE_URL="https://github.com/${PFM_RELEASE_REPO}/releases/download/${PFM_RELEASE_TAG}"
PFM_RELEASE_TMP="$(mktemp -d)"
cd "$PFM_RELEASE_TMP"
curl -fLO "${PFM_RELEASE_URL}/${PFM_RELEASE_BINARY}"
curl -fLO "${PFM_RELEASE_URL}/SHA256SUMS"
awk -v file="$PFM_RELEASE_BINARY" '$2 == file' SHA256SUMS > "${PFM_RELEASE_BINARY}.sha256"
test -s "${PFM_RELEASE_BINARY}.sha256"
if command -v sha256sum >/dev/null 2>&1; then
  sha256sum -c "${PFM_RELEASE_BINARY}.sha256"
else
  shasum -a 256 -c "${PFM_RELEASE_BINARY}.sha256"
fi
mkdir -p "$HOME/.local/bin"
install -m 0755 "$PFM_RELEASE_BINARY" "$HOME/.local/bin/pfm"
hash -r
pfm version
```

Stop if the checksum row is missing, validation fails, or `pfm version` does not print `v0.61.0`.
Then preview and apply the host reconciliation:

```bash
pfm install
pfm install --yes
```

Use `--skip-harvest` on both commands only when the operator intentionally leaves the pinned
Harvester runtime unmanaged. It is not a bypass for a failed provision. If the installer names a
live-service jail guard, follow the exact stop/jail instruction and retry.

#### 3. Validate the machine lane end to end

Run:

```bash
pfm version
pfm config validate
pfm config show
pfm doctor
pfm mcp ls
pfm ls --tsv >/dev/null
```

Acceptance requires:

- `pfm version` reports exactly `v0.61.0`, and configuration remains effective schema 2.
- Only real Codex account homes appear under `codex.homes`; OpenCode uses its own native store.
  Never add a proxy or shadow Codex directory as an account.
- Atlassian and other unwanted third-party MCP servers stay disabled. Professor's Chat and
  Harvester routes are exact `127.0.0.1` URLs with no bearer token or Authorization header; they
  are intentionally local and unauthenticated. Never expose the shared daemon beyond loopback.
- `pfm doctor` reports the Harvester sidecar healthy and
  `pre-push gate=armed core.hooksPath=.githooks` in a maintainer checkout. A normal adopter project
  need not arm Professor's repository hook.
- Automatic Dream/STM hooks remain absent. Do not re-enable or read STM as part of the update.

When an ask adapter is configured, prove both Harvester spellings and failure receipts with a
temporary public fixture:

```bash
PFM_SMOKE_FILE="$(mktemp)"
printf '%s\n' 'Professor release v0.61.0' > "$PFM_SMOKE_FILE"
pfm harvest ask -p 'Return only the version in this file.' "$PFM_SMOKE_FILE"
pfm harvest --ask -p 'Return only the product name in this file.' "$PFM_SMOKE_FILE"
pfm harvest ask -p 'Name the unavailable source.' "$PFM_SMOKE_FILE" "${PFM_SMOKE_FILE}.missing"
```

Require cited evidence for the readable file and an explicit unavailable/error receipt for the
missing source. A failed source that disappears from the answer corpus is a regression.

Test reload on a disposable chat, never on the updating chat:

```bash
PFM_CANARY_NAME="reload-canary-$$"
pfm chat new --name "$PFM_CANARY_NAME" --engine cx --await 'Reply exactly RELOAD_CANARY_READY, then wait.'
PFM_CANARY_SOCKET="$(pfm chat resolve "$PFM_CANARY_NAME" | cut -f1)"
test -n "$PFM_CANARY_SOCKET"
pfm chat reload --sock "$PFM_CANARY_SOCKET" --then 'Reply exactly RELOAD_CANARY_RESUMED, then wait.'
pfm chat status "$PFM_CANARY_NAME" --json
```

Require the canary to reply `RELOAD_CANARY_RESUMED` and return to idle with an empty composer. Do
not count the echoed continuation prompt as the reply, and do not press Enter on the canary's
behalf. If the test fails, inspect the named reload log and the canary pane; leave the updating chat
untouched.

Finally, start a new or reloaded Codex/OpenCode session and verify its agent registry exposes every
Claude source role, including `gitter`. Ask `gitter` for a read-only `git status --short` and wait
for its actual report; merely starting the child is not a completed test. All other roles must
remain Git-read-only.

#### 4. Update each installed project blueprint lane

Run this lane once per project containing `.professor/manifest.json`:

1. Preview the semantic update:

   ```text
   /pcm:update check --to v0.61.0
   ```

2. Review every auto-apply, review, and manual bucket. Preserve `.professor/drift.md` KEEP-LOCAL
   entries. Hook, permission, environment, model, MCP, and account changes always require operator
   approval. Generated files are whole-file compiler outputs, never line merges.
3. Apply the accepted update:

   ```text
   /pcm:update --to v0.61.0
   ```

4. Rebuild and verify all enabled runtime mirrors:

   ```bash
   pfm codex build .
   pfm codex check .
   if [ -f .claude/scripts/build-opencode.mjs ]; then
     node .claude/scripts/build-opencode.mjs generate
     node .claude/scripts/build-opencode.mjs doctor
   fi
   ```

   `AGENTS.md`, `.codex/`, and `.opencode/` are generated outputs. Fix their source or compiler when
   a check fails; never hand-edit a generated mirror.

5. Start a new or reloaded runtime session so it discovers the refreshed agent registry. Verify
   Codex and OpenCode expose the same source-agent names as Claude and that only `gitter` can write
   Git.
6. Run the project's real build, typecheck, full test suite, and leak/secret gate. A skipped or
   unavailable toolchain is a named gap, never a pass.

#### 5. Maintainer publication checks

This section applies only to a clone that will publish Professor itself:

```bash
git config core.hooksPath .githooks
pfm doctor
node scripts/check-agent-roster.mjs
scripts/leak-check.sh
```

Require the doctor row to say the hook is armed, the roster gate to enumerate equal Claude/Codex/
OpenCode agent sets, and the leak gate to run. Before any push, run Professor's isolated blueprint,
PFM, PFM e2e, and walker gates through `.claude/scripts/dev.sh`; never treat missing pre-push output
as success.

#### 6. Final handoff

Report separately for the machine lane and each project:

- old → new version and whether update or direct bootstrap was used;
- official asset name and checksum result for a bootstrap;
- files and host surfaces changed;
- config, Codex-account, OpenCode, MCP, Harvester, and STM choices;
- auto-applied, reviewed, kept-local, and manual migration counts;
- reload canary PID/session evidence and the completed gitter read-only result;
- exact validation/test commands and exit results;
- every unresolved warning or unavailable gate;
- final `git status --short` for every repository.

The upgrade is complete only when the machine lane reports `v0.61.0`, configuration and doctor
pass in the selected mode, every project records `v0.61.0`, generated runtime checks pass, the
disposable reload continuation replies, and no pre-existing local change was discarded.
