# v0.70.0 — 2026-09-07

Stability release. The `/p:tokens` alias and the `p/` namespace it revived are gone end to end, and `pfm install` now prunes the orphaned registry link a retired global command leaves behind. Four gates that could report the wrong thing about their own health were corrected: the Codex dangling-source check classifies by a typed condition instead of grepping its own prose, the mirror Stop hook names which stage failed instead of blaming the compile, the scaffolded Stop hook's guard markers match the paths the guards actually write, and the self-hosted manifest gate is satisfiable again and states what it excludes. A new `/pfm:refresh` command re-derives the blueprint from a live source project, hunk by hunk, in reviewed batches.

## Removed

- Minor: global commands — the `/p:tokens` compatibility alias and the `p/` command namespace it revived are removed. `p/` was retired wholesale in v0.66.0 (`p/tokens`→`/tokens`, `p/rnd`→`/rnd`); the alias returned in v0.69.0 on the premise that the pinned legacy Wave Walker bundle required it. It does not: the bundle never invokes the command, it prints a report footnote naming the skill, and the engine source already names `/tokens`. Token attribution has one name again.
  #### → For: adopters — `pfm install` retires the orphaned `~/.claude/commands/p` link and `pfm codex build` drops its compiled `p-tokens` twin; nothing to hand-apply. Anyone who typed `/p:tokens` types `/tokens`.

- Patch: templates/project/commands/dev.md — § 0b documents the `cmd_up()` env-file bootstrap (a roster entry's missing `.env.local` is seeded from that project's own `.env.local.example`, with required secrets filled from the infra project's secrets file, so the example must carry every key the project's env module requires), and the `### ISO LIST` subsection that restated the ISO routing bullet verbatim is removed.

## Added

- Minor: skills — `architecture-design` becomes a machine-global skill shipped in-tree at `templates/global/skills/architecture-design/` instead of a per-project copy: it designs a codebase's layout for agent maintainers (one directory per unit of change, fixed file anatomy, grep-true names, façades, the reader's path — brief anchors, consumer index, work-tree anatomy, ceiling ratchet) and emits a design document, greenfield or brownfield. Project nouns are parameterized — the contracts hub reads as "the roster's wire-contract/schema hub (when it has one)" and its consumer index as the command the root `CLAUDE.md` § Architecture names, so the skill carries no repo-specific script.

## Changed

- Mechanics: `pfm install` — `wireGlobalSkills` now links every top-level DIRECTORY under `templates/global/skills/` into `~/.claude/skills/{name}` as one whole-directory symlink (the idiom the global-commands registry already uses), beside the in-tree `engines/deep-rr` link. The `sources.json` registry sitting among them is a file, never linked as a skill; a skill source without a `SKILL.md` is reported `SKILL-SOURCE-MISSING {name}` and left unlinked; an absent or empty source directory is reported, never an error. (safe-auto)
  #### → For: adopters — `pfm update` rebuilds the binary and refreshes the registry symlinks; nothing to hand-apply. A project holding its own copy of a now-machine-global skill under `.claude/skills/` can delete it — the host-global link supersedes it.

- Docs: BLUEPRINT.md · docs/README.md · SETUP.md · INSTALL.md — the machine-global skill surface is documented as `templates/global/skills/` (shipped skill directories plus the `sources.json` fetch registry), with `architecture-design` listed in the skill roster, the SETUP source table, and the `~/.claude/skills/` symlink list.

## Fixed

- Patch: tokens — `token-ledger.mjs` `PRICING` Codex rows carry the vendor's published standard-tier rates by literal model id (`gpt-6-astra` 10/1/50, `gpt-5.6-sol` 4/0.40/20 promotional through 2026-11-21, `gpt-5.6-luna` 0.20/0.02/1.20; source + read date in the comment) in place of the `{CODEX_MODEL_*}` placeholders — a symlinked global template is never rendered, so those rows matched nothing and every Codex session priced `n/a`; README § Cost model follows; the `{CODEX_MODEL_*}` tokens stay registered — `templates/project/scripts/build-codex.mjs` still renders them
  #### → For: adopters running other Codex model ids add their own literal rows; re-pull is enough for symlinked installs

- Patch: pfm install (cost) — new `retireOrphanGlobalCommands` prunes a `~/.claude/commands/{name}` symlink whose `templates/global/commands/{name}` source no longer ships. `wireGlobalCommands` links what the source HOLDS and never pruned what it stopped holding, so every global command retired upstream left a dangling registry link in every adopter's install forever; the Codex mirror has prevented exactly this since codexgen grew orphan reconciliation, and this is the Claude-side half. Ownership is decided by the link's TARGET, never its name — an operator's own command, a link resolving elsewhere, and a dangling personal link outside the blueprint all survive.

- Patch: wave-walker — the stale `p:tokens` pointer in `src/types/run.ts` names `/tokens`, matching `src/utils/index.ts`. The frozen `dist/workflow.js` legacy bundle keeps its own string under the immutability law in `engine/design.md`.

- Patch: codex-sync.sh — the Stop hook's block now names WHICH stage failed (`codex build` / `codex check` / `opencode generate` / `opencode check`) and prints only that stage's output. It previously reported "a runtime mirror failed to compile" for any failure and dumped every stage's log, so a check-only failure printed `CODEX BUILD PASS` directly beneath a message claiming the compile broke — sending the reader to repair something that was not broken. A build failure and a verification failure are different defects with different repairs, and the stage name is what distinguishes them; the template twin, which short-circuited on `build && check` and so could not tell them apart at all, now runs both stages and reports the same way.

- Patch: pfm codex check — the dangling-source gate classifies by a TYPED condition instead of a substring of rendered prose. `Result` gained `Dangling []string` and a `danglingSource()` recorder that every emitter now calls; Check promotes those entries to Problems. Previously both Check paths re-scanned `result.Warnings` for the literal text "dangling", a coincidence detector on its own message wording: rewording a warning silently disarmed the gate, and any unrelated warning carrying the word armed it against nothing. The build-tolerates / check-gates asymmetry is deliberate and unchanged; what changes is that the gate now keys on the condition rather than on prose, and each promoted problem carries its remedy — `pfm install` prunes an orphaned global-command link automatically — so a Stop hook blocked on one names the way out instead of looping on a state re-running cannot clear.

- Patch: templates/project/scripts/notify.sh — the Stop hook's marker paths use the literal `professor_` prefix that `pfm-guard.sh` and `guard-stamp.sh` already use, replacing `{CHARACTER_NAME_LOWER}`, a token registered in neither `docs/PLACEHOLDERS.md` nor `scripts/placeholder-map.tsv`. Nothing substituted it, so a scaffolded install wrote and reaped `/tmp/{CHARACTER_NAME_LOWER}_turn_start` with the braces intact, and the gate markers `notify.sh` cleared could never be the ones `pfm-guard.sh` writes and `guard-stamp.sh` globs. The prefix stays a literal across all three because `pfm-guard.sh`'s deny message hands the operator that exact path to stamp — a filename the reader must type is one the three files have to agree on byte-for-byte.

- Patch: infra/check-self-hosted-manifest.sh — the file_hashes coverage set now includes only tracked paths that can actually be hashed, and NAMES each exclusion on stderr (`NOT-HASHABLE {path} … verified by nothing`). A tracked symlink-to-directory under the installed surface made the gate unsatisfiable: coverage demanded the path while the verification loop's own `-f` test rejected it and `sha256sum` answered "Is a directory", so no manifest could pass. The gate had been red since the tracked symlink landed and nothing noticed, because it runs only at release; an exclusion is now a stated fact rather than a silent one, since "covered by nothing" and "excluded because unhashable" are different results.
