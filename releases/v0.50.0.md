# v0.50.0 — 2026-08-04

## Added

- Mechanics: `ENGINES/wave-walker/` — the walker engine's full TypeScript source moves INTO the blueprint repo (src, 337-test vitest suite, dependency-derived concatenating bundler, `validate-bundle` gate). `npm run build` in `ENGINES/wave-walker/engine/` emits the universal bundle at `dist/workflow.js`; the clone is the engine's single home and `git pull` is its whole update story — the per-project bundle-drift era ends here.
- Mechanics: `workflows/wave-walker.js` — the bundle is now **universal**: every project-specific value (auth doc + fallback rule, role names, resource classes, fence labels, gate-relevance regexes, deadness surfaces, stakes line) arms at runtime from `args.project`. Absent or invalid profile → the gate machinery reports `gates: SKIPPED — no project profile supplied` in Coverage and telemetry — loud, never silent; thread walk, security fan-out, and panel modes run fully regardless. (breaking)
  #### → For: pass the § Engine profile block as `args.project` on every engine invocation; without it R6/R7 and gate sweeps no longer arm.
- Tier A: `commands/wave/walker.md` — new **§ Engine profile (`args.project`)**: each project writes its profile block ONCE at initiation; every invocation passes it verbatim. Walk-args list and the scout's fallback-rule reference updated to match.
- Tier B: `skills/legal/` — vendored 12-file legal reference shelf (DPA review + drafting, DPIA, breach response, privacy notices, vendor due diligence, NDA triage, statute analysis, adversarial legal QC, skill-optimizer, and the pre-delivery self-check every draft must pass), distilled with per-file attribution and licenses intact; domain nouns placeholdered to the canonical token set. First vendored skill — `sources.json` remains the home for source-fetched ones.
- Scripts: generated-bundle banner — every built bundle opens (immediately after `meta`) with `⚠ GENERATED FILE — DO NOT EDIT`, and `validate-bundle.js` permanently FAILS any build whose bundle contains a project-leak term. The banner is machinery, not decoration: the update protocol keys on it.

## Changed

- Mechanics: `commands/pcm/update.md` — **atomic-artifact law**: a banner-carrying generated file (and any built bundle under `.claude/workflows/`) is applied as a whole-file copy or a rebuild by its stated generator — NEVER a line-merge, in any bucket. A partial merge produces a bundle whose `meta` claims behavior its body does not contain — a lying instrument (observed live: a 19-line hand back-port advertising a security fan-out the code lacked). A symlink into the blueprint clone is never written through — the clone's `git pull` is its update channel. Every Bucket-1 apply is a byte-for-byte copy, not a model-mediated re-edit. (safe-auto)
- Docs: `README.md` — repo-layout `skills/` line and a Legal-shelf row in What ships.

### Migration

- → For adopters: replace `.claude/workflows/wave-walker.js` with a symlink to `{clone}/ENGINES/wave-walker/engine/dist/workflow.js` (or copy the new template file), then write your § Engine profile block into `.claude/commands/wave/walker.md` — values come from your manifest's domain vocabulary plus the same adoption judgment your original walker parameterization recorded (roles, fenced resource classes, gate paths). Until the profile lands, walks are thread-walk-only with gates loudly SKIPPED.
