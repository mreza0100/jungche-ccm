# v0.46.0 — 2026-07-31

## Added

- Feature: wave/walker — Fast mode (`walker fast <mission>` / "fast walk"): inline consumer-tree trace, no Workflow — one Sonnet lead + parallel Haiku tracers under the sync-dispatch law (all Agent calls in ONE message, awaited in-turn; a missing report = a loud named coverage hole), closed-world hit inventory with per-file dispositions (EDGE/RED-HERRING/NOT-MINE/FRONTIER/FAILED-TO-LOOK), spelling sets, absence-only-via-mechanism, quote-pinned edges, merge duties (name-the-reader, shapes-not-diffed, mounted-or-dead, guards-quoted-per-resolver), git-stamp + reconciled telemetry; frontmatter description routes the fast triggers. RND-proven against a hand-built ground truth (ties a very-thorough Explore's recall at ~63% of its cost).
  #### → For: adopters swap the § Fast mode Recipes table's repo anchor paths for their own projects — the protocol is repo-agnostic, the anchors are not.

- QA: qa-commons § Test economy — six acceptance gates every QA-written test passes (reuse-first, fail-without-fix, parametrize-siblings, extend-don't-accumulate, retire-by-the-same-gate, report-the-net). The QA objective function previously had no term for the cost of a test: a coverage floor with no ceiling, a per-wave new-file mandate, and no reuse or subtractive rule anywhere across the agents or the shared card. Cited from every `qa-{project}` protocol at its write-tests step; the `**Where:**` lines that read as "new file every wave" now point at the module owning the contract area.
  #### → For: adopters get retroactive test retirement for free — the fail-without-fix gate runs backwards (break the contract, a test that still passes pins nothing), turning "is this test worthless" from inspection into evidence. Prompt-text, schema, domain value-set and absence-guard tests are exempted from that gate by name and stay under human review.

- QA: qa-commons § Test validity — six gates asking whether a test tests anything, sibling to § Test economy's "is it worth keeping": reaches-production, asserts-the-assembled-artifact, name-honoured, substring-names-its-subject, counts-derived-never-literal, and a scan that can return empty asserts non-empty first. Cited from every `qa-{project}` protocol. Root CLAUDE.md § Testing gains the three cross-cutting forms (a test reaches production or it is not a test; tier by boundary not directory; one number, one home).
  #### → For: adopters get the failure shapes these were derived from — a suite that rebuilt the resolver map beside the one the server assembles (15 auth mutations "covered" while unwired from the live schema), tests re-implementing a routing branch inline and asserting against their own copy, a substring assertion matching a different type's field for years, and a guard counting files instead of contracts that passed vacuously on an empty scan.

- QA: qa-commons § Isolation on suspicion — a gate failure whose shape is infrastructural (timeout, hook, teardown, spawn, connection) is re-run ALONE on an idle box, through the project's own runner, before it is called a defect. A gate run shares the box with whatever else is running, so one run reports the same verdict for a broken build and a busy machine — and reporting either reading from it decides nothing. One isolation round rules: passes alone = contention, reported as BOTH readings ("failed in the full run, passed 3/3 isolated") and never as the isolated one by itself; fails alone = a real defect into the fix loop; isolated runs disagreeing with each other = the test is flaky and that is the finding, `BUG-FLAKY-TEST`. An assertion failure is a bug on first showing and never qualifies, so this cannot decay into retry-until-green. Closes with the label-trust rule: read a failure's own text before believing it, since runners mislabel which hook fired and a profile that printed a passing scenario tally already ran its scenarios.
  #### → For: adopters whose runner cannot be driven for a single suite/profile get nothing from this — the rule names the project's own runner deliberately, because invoking the underlying test tool bare skips the loader and per-worker env and dies with a module-resolution error that reads exactly like a real break. New vocabulary: `BUG-FLAKY-TEST`, defined in the same card that raises it.

- Framework: /quality:prompt — second axis added: a `§ Correctness & model behavior` section beside the leanness rules (frontmatter + intro now name both axes). Rules: compute-don't-ask numbers (inject a code-computed `{var}`; illustrative numbers stay "e.g.", the injected value is the only cap); no conflicting directives (gas-and-brake) + rules-interact regression testing (test a change against the OTHER failure modes); structure/order (job first · define-before-use · explain-every-slot · critical-constraint-last for recency); translated-prompt-is-a-NEW-prompt per-language validation; and a when-a-rule-is-disobeyed escalation ladder (contrastive example → positive reframe → shape-the-input/enforce-in-code) that chains into the existing Teaching-by-example + Enforce-invariants sections. Anti-pattern 7 gains the empirical do-not-collateral anchor.

- Framework: Codex first-class parity — `codex-mirror.sh` mirrors every command and skill into `.codex/skills/`, so a Codex session routes the same entry points Claude does, under their exact names. Two shapes, forced by the harness and not a preference: directory-shaped entry points stay relative symlinks; single-file commands each get a generated `SKILL.md` carrying the source's verbatim frontmatter plus one line pointing at the source file — repo-relative, never absolute, so worktree lanes read their own branch's protocol. Reason, live-probed at codex 0.144.1: Codex follows a symlinked skill DIRECTORY but silently drops a real directory whose `SKILL.md` is a symlinked FILE — the obvious file-symlink mirror registers nothing and warns nobody (measured 9 discovered skills before, 56 after, same 56 dirs on disk). `check` mode exits non-zero naming every pointer that drifted from its source or was replaced by a symlink; hand-written Codex cards are skipped by name so a bridge card is never clobbered by a generated pointer.
  #### → For: run `codex-mirror.sh generate` after adding or renaming any command or skill, and `codex-mirror.sh check` wherever registry integrity is gated. Adopters with no `.codex/` are unaffected — the script is inert without one.

## Changed

- Framework: root response format — removed the mandatory `Expected:`/`Got:` contrast from every finding, bug, and mismatch; responses may now use the clearest task-specific structure.

- Framework: /quality:prompt ↔ /pcm scope split — /quality:prompt is now consumer-agnostic prompt law only (cut test, compaction, anti-patterns generalized: "the model" not a specific assistant, harness examples removed); every harness-specific rule moved to a new `/pcm § Claude-harness prompt law` (hard-thresholds table, harness prompt-stream composition, voice-location + output-styles routing, hooks-vs-prompts, where-content-goes table); both files cross-point one level deep.
  #### → For: adopters re-read /quality:prompt if they vendored it; any doc citing "/quality:prompt § Hard thresholds" or "§ Where things go" retargets to /pcm § Claude-harness prompt law.

- Framework: Codex lane — native subagents, evidence-first: live probes proved codex 0.144.1 spawns anonymous forked children (`spawn_agent{task_name,message,fork_turns}`, no agent-selection param — the documented `.codex/agents/*.toml` custom-agent registry is INERT in this build at every scope and flag), so the wave-builder lane now carries the working dispatch shape (per-role `spawn_agent` children whose message binds the protocol pointer, stamping an executor id; inline stays valid; GATE-1 QA stays inline) and `.codex/agents/` ships the role TOML registry in the documented format — self-activating when a codex release wires custom agents; gitter deliberately unregistered (git is execpolicy-forbidden for Codex). Headless smoke tests green: children spawned, read their protocols, stamped correctly.

- Framework: Codex lane — root-agent bridge: an `agents-root` symlink (→ the root agent registry, same relative pattern as the builder-peer bridge) added to the wave-builder skill dir + its Toolset card line — Codex lanes now see the full root registry (gitter, mono-documenter, `qa-{project}` wrappers) as orientation reading; gitter stays never-inline (git is forbidden at the rules layer), qa wrappers already route to the child qa protocol.

- Framework: Codex skill registry — the RR skill is now reached by symlink rather than a divergent copy, exposing it to Codex without vendoring; Codex uses the inline `rr fast` path.

- Framework: wave/walker — contradictory verdicts on ONE file now ESCALATE instead of averaging. A zero-token scan pairs every thread-walker verdict to the files its thread spec names; where two or more seats walked the same file and disagree (one INTACT, another AT-RISK/BROKEN) the pair reaches the final judge as a NAMED contradiction with an explicit no-averaging duty — open the file, name which seat is wrong, VOID a verdict resting on evidence the file does not contain — and the fold must carry it in Coverage with the ruling, marking a voided thread verdict VOID in the Thread Walk table. The scan publishes its own coverage line on every walk, zero included (files compared; every walked thread whose spec named no files, uncomparable and never counted as agreement). Additive and byte-identical when nothing conflicts: both prompt appends are zero-bytes-when-empty.
  #### → For: an adopter whose walkers return verdicts without a per-thread `files` list sees every thread reported as uncomparable — the scan says so out loud rather than reporting agreement; have the scout name files per thread to get contradiction coverage.

- Framework: wave/walker-invariants § Registry Format — every exemplar now carries a STATUS (LIVE, or FIXED naming the pin that closed it) and hunters re-read a cited line before treating it as evidence, naming a stale anchor in their coverage. An exemplar rots the moment its bug is fixed; unmarked, it sends a hunter to an anchor that no longer holds and teaches it the registry cannot be trusted — the silent-bad-entry failure the registry's own § Curation warns about.

- Blueprint: the Codex layer is re-derived from what actually runs, replacing a design that did not. The shipped layer described Codex Teams orchestration (`Agent(role, "...")` dispatch, `CODEX_EXPERIMENTAL_AGENT_TEAMS`, `[agents] max_threads/max_depth/job_max_runtime_seconds`) — a mechanism codex 0.144.1 does not have. Removed: 14 command-wrapper agent TOMLs for that model, and 23 hand-vendored skill directories that are generated output (their colon names — `wave:refine` — are flattened to hyphens by the mirror, so they were wrong on two axes). Added: per-project role TOMLs as a `{project}`-tokened pattern, `mono-documenter.toml`, the `codex-mirror.sh` generator, and hand-written `wave-builder` + `chat` bridge cards. `config.toml` re-derived from live; the README rewritten around `spawn_agent` reality, the inert-but-forward-compatible registry, and the two pointer shapes. A "Settings deliberately absent" table records each removal so an upgrading adopter reads it as *untrue*, not as *trimmed*.
  #### → For: an adopter running the old Codex layer should re-read `templates/codex/README.md` end to end — the orchestration model it replaces never worked, so anything built on it needs rechecking. Run `codex-mirror.sh generate` to produce the skills layer instead of copying vendored directories.

- Blueprint: `chat:*` ships as a HOST-level command family, joining `bb` and `swap` in the host bundle instead of `templates/commands/`. A project-level chat install is a set of relative symlinks that break inside a worktree at a different directory depth; installed to the user's home it resolves in every repo and every worktree. `codex-mirror.sh` gains a second pointer class to match — repo commands keep repo-relative pointers so a lane reads its own branch's protocol, host commands get `$HOME`-anchored ones, and the coverage line reports the two counts separately.
  #### → For: move `.claude/commands/chat/` to `~/.claude/commands/chat/` and delete the project copy, then re-run `codex-mirror.sh generate` if you use the Codex layer.

## Fixed

- Framework: wave/walker — the four instrument defects from the 2026-07-28 audit (two full walks each returned a 0-finding security sweep over a diff holding a critical data-loss path, a dead login feature, and a fake test pin) are closed in the engine. D1 file-set reconciliation: the scout returns `changedFileCount` — a separately-executed count of the same name-only diff, REQUIRED in the schema, never the length of its enumerated list; the engine reconciles the two with one corrective retry naming both numbers, then FAILS the walk (the empty-set guard's law one altitude up: an untrusted denominator never renders a verdict). D2 security fan-out: the only lens with no fan-out now scales like every other seat — changed files cluster sorted into slices of ≤`securityFilesPerAuditor` (default 12, new walk arg), one Sonnet-xhigh auditor per slice with the full set as cross-file context, each returning `filesOpened`/`filesSkipped`; the merge concatenates findings (per-slice id prefixes), INTERSECTS `categoriesSwept`, and NAMES every unopened changed file unswept — every headline now carries auditors returned/dispatched + files opened/in-scope; null only when every slice died (AUDIT DIED stays an explicit hole). D3: the code-hygiene audit doc is now HANDED to every thread walker via `CONFIG.HYGIENE_DOC` — § Role: Walker step 4 had cited it from day one while no seat ever received it (the phantom-citation class). D4: the producer-verification clause on threadWalker/anomalyJudge/securityAuditor prompts — a claimed shape-fix is verified against the code that EMITS the shape; a test's fabricated envelope is never evidence (four seats had certified one).
  #### → For: adopters parity-pinning prompts re-transcribe the scout/securityAuditor/threadWalker/anomalyJudge/finalJudge/fold fixtures; a scout result without `changedFileCount` now FAILS the walk BY DESIGN (the pre-feature shape is an untrusted denominator). (cost: ~⌈N/12⌉ Sonnet-xhigh security auditors per walk instead of 1 — the single auditor was the defect.)

- Blueprint: `templates/codex/rules/default.rules` permitted Codex to run `git add`, `commit`, `merge`, `checkout` and `push`, justified in-file as "Codex owns its own commits when orchestrating" — the exact inverse of load-bearing wall #1, *only gitter touches git*. It also carried a `prefix_rule` matching `edit`, which is not a command any runtime executes, so it could never fire: decoration reading as protection. The file shipped as the door lock while unlocking the door. Deleted and replaced by `repo-law.rules`, the three infra forbids the live rules file converged on after months of real lane use, plus a commented-out optional git-pin block that states honestly that the live setup relies on prose law rather than the pin.

- Blueprint: the Codex README claimed "Codex has NO git access — the sandbox blocks `.git/` writes." False in the reassuring direction: git is not gated at the harness at all, which is precisely why the prose ban must be absolute. A comment asserting a security property it does not have retires the vigilance that would otherwise catch the gap. Corrected, and the README now names the pin (or its absence) for every protection it claims.

- Blueprint: `templates/host-swap/swap.command.md` instructed the reader to invoke a swap script the bundle does not ship, and `cc-account-swap.sh` + `cc-launch.sh` documented a superseded macOS-Keychain flow with no live source. The broken reference is removed, the two dead templates retired, and the bundle's install story corrected. The bundle also gains the real fixes from this round: a `flock` takeover mutex closing a race where two terminals opening one row could both reclaim and corrupt a transcript, fail-closed busy detection (a failed query now skips rather than assumes idle), and removal of a fallback that could target the wrong session entirely.
