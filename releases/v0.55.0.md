# v0.55.0 — 2026-08-17

An audit asked a simple question: what can an adopter learn about this engine from its own release
logs? The answer was seven shipped commits the log never mentioned, a setup step promising five hook
wirings the installer performed one of, and nine subcommands with no adopter-facing sentence
anywhere. This release ships that work, corrects the record, and makes the promised wiring true
rather than rewording it down to what the code happened to do.

## Added

- Tier B: pfm — `/clear` hides the completed Claude or Codex chat until its transcript grows; Codex completes the hide on the fresh chat's first prompt, `/exit` stays unchanged, and `/bb` retires across commands, skills, and hook wiring. (hook)

  #### → For: run `pfm install --apply` once. It wires the `SessionEnd` hook for Claude and the

  `SessionStart` hook for Codex, and retires the `/bb` command link, skill link, and stale
  `UserPromptSubmit` entry it previously owned. A file it did not install is never touched.

- Tier C: pfm — `/chat:branch` creates a detached fork without changing the current pane, named chats resolve before their first prompt, and a bare fleet terminal closes with its harness.

- Tier C: pfm — the Stats rate column becomes `TOK/MIN`, measured from token growth across a
  one-minute sliding window. The column previously reported lifetime tokens divided by transcript
  age, so a chat idle for fifty-eight hours still read as roughly two million tokens per hour — a
  description of its history, not of anything happening now. The first sample renders unknown, a
  window with no growth renders idle, and a truncation, rotation, session change, or pruned cache
  entry resets the baseline rather than counting the discontinuity as growth. Golden renders pin an
  active, an idle, and an unknown row at both widths. (safe-auto)

## Changed

- Tier C: pfm — the picker re-scans every four seconds, agent rows use an orange identity distinct from Codex, and labeled Stats properties carry metric-specific colors.

- Tier A: `pfm install` — the group hook and the `/clear` hook now reach **every** account settings
  file the installer visits, not the canonical one alone. Previously both were conditional in ways
  no document disclosed: the group hook was only ever rewritten from an existing `chat/group.sh`
  entry and never appended fresh, and the `/clear` `SessionEnd` hook was appended only to the
  canonical config dir — so an adopter running real per-account settings files got the hooks on one
  account and silently nothing on the rest. Both are now appended where absent and deduped where
  present, and a second apply remains a measured zero-change run. Uninstall stops guessing along
  with it: a private `0600` ledger beside the staged assets records the hook occurrences this
  installer added or migrated, per physical settings path, and `--uninstall` removes only those — an
  identical command you wired by hand survives, and an uninstall that cannot reach a settings file
  it owns hooks in refuses rather than stranding them. (cost: existing account settings files gain
  two hook entries on the next apply; each is backed up first)

  #### → For: run `pfm install --apply` once; review `pfm install --dry-run` first if you keep

  hand-edited account settings.

- Tier B: `pfm install` — a legacy dreamer hook command migrates to its native verb in place:
  `dreamer-agent-inject.sh` becomes `pfm dream hook agent-inject` and `dreamer-nudge.sh` becomes
  `pfm dream hook nudge`, on the event each already occupied. Migration only — a settings file with
  no dream hook does not acquire one, so an adopter who never ran the dreamer is unaffected. A
  migrated hook is installer-owned from then on, so `--uninstall` removes it rather than restoring a
  shell command whose script no longer exists in the tree.

- Docs: `INSTALL.md`, `blueprint/SETUP.md` § 7g — the fleet installation step now names the six
  surfaces `pfm install --apply` writes (staged assets, command symlinks, systemd user units, Claude
  account settings, `~/.codex/hooks.json`, and the `~/.zshrc` source line), states that dry-run is
  the default mode, that a reachable `systemd --user` bus makes the installer refuse before any
  write, and that `pfm install --uninstall` reverses it.

- Docs: `README.md` — the host layer names the maintenance verbs an operator actually reaches for:
  `heal`, `reap`, `archive`, `revive`, `index`, `doctor`, and `dream`. `heal` in particular had no
  adopter-facing sentence anywhere while its source was linked publicly from an upstream Codex issue.

## Fixed

- Tier B: dreamer — legacy lane surfaces migrate atomically to map-backed memory on first hook consultation, with tracked-source and ownership checks.

- Tier C: pfm — Stats treats a transcript that disappears during refresh as unknown token usage instead of painting the expected race as a warning.

- Docs: `blueprint/SETUP.md` § 7g claimed the installer "wires the native statusline, usage, group,
  dream, and `/clear` SessionEnd hooks across existing canonical account settings". Only the usage
  hook was unconditional. The statusline is set only when none exists or an old shell statusline is
  being migrated; the group and `/clear` hooks are corrected in code above; dream wiring did not
  exist in the installer at all. A setup step that overstates what an installer does sends the
  adopter looking for a bug in their own machine.

## Removed

- Tier A: `/bb` — the command, its jail test, its embedded command card, and its Codex skill asset
  are gone, and the installer retires the wiring it previously owned. `/clear` is the disposal path
  now, and it needs no command at all.

  #### → For: stop typing `/bb`; clear the chat instead. If you kept a local copy of the `/bb` card

  or skill, delete it — the installer will not remove a file it did not install.

## Migration

- Tier A: adopters on v0.54.0 — rebuild and reinstall once:

  ```bash
  go -C "$HOME/.professor/pfm" build -o "$HOME/.local/bin/pfm" ./cmd/pfm
  "$HOME/.local/bin/pfm" install --dry-run   # review
  "$HOME/.local/bin/pfm" install --apply
  ```

  The apply is idempotent, backs up every file it rewrites, and refuses outright if a
  `systemd --user` bus is reachable (rc 97) rather than writing a half-configured host.
