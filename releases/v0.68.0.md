# v0.68.0 — 2026-09-04

## Added

- A: pfm — `tmux.titles.enabled` (default `true`) gates the `set-titles` / `set-titles-string` options pfm used to force on every server it spawned — `false` leaves a host that sets its own OSC title before tmux starts untouched; `pfm internal tmux-titles` feeds the shim the same policy, and `pfm doctor` reports per live socket whether the title is pfm-owned or host-owned (issue #14 F10, corrected).

## Changed

- pfm: chat_inject / `pfm chat inject` refuse a pane whose operator typed within `CHAT_INJECT_TYPIST_QUIET` (3s, tmux `client_activity`; `force_now` overrides) and the `--then` waiter holds instead of typing over them — a tmux read failure reports "could not read", never "nobody typing"; the blind second Enter and `EnterGap` are gone (a re-Enter needs the composer to visibly still hold the message); `/compact` is refused on chat_inject and lives only in `Engine.ScheduleSelfCompact` behind `chat_self_compact` and the new `pfm chat self-compact --then STEER FOCUS`; the then-log is per socket+pane; `TestRealClaudeStashSemantics` (REAL-SESSION, `PFM_REAL_CLAUDE=1`) pins Ctrl+S: one slot, last write wins, pop on empty, "Draft restored" after a submitted turn. (fdd11eb)

- A: pfm — `pfm install` owns the two host overlays it used to leave to hand-made symlinks: `pfm-statusline` (context-gauge overlay) and `tmux-title-renudge` are installer assets materialised under `~/.local/share/pfm/install/bin/` and linked from `~/.local/bin/`; an empty, legacy, or bare `pfm statusline` `statusLine.command` is pointed at the overlay (any other custom command is preserved), and `pfm doctor` fails when a link is missing or displaced or the raw command is still wired. The installer also retires the pre-rename `~/.claude/agents/frr.md` it left behind, and `tmux-title-renudge` exits 3 with a message when every live server has `set-titles off` instead of reporting a silent success, and looks under `$TMUX_TMPDIR/tmux-<uid>/` (it read `$TMUX_TMPDIR` itself, nudged nothing, and exited 0) (issue #14 F1, F5, F10).
#### → For: `pfm install --yes` wires the links and rewrites a raw `pfm statusline` command (safe-auto).

- A: pfm — a Claude `/rename` reaches the tmux window name on the next statusline render (main chat, inside a pfm socket, once per label change through the same `gather.WindowNameFor` + `RenameWindow` name-sync uses) instead of waiting for the 15-minute poll; `nameSync.interval` (default `15m`, min `1m`) renders into both the launchd `StartInterval` and the systemd `OnUnitInactiveSec` from one value; `pfm name-sync` counts only a rename it read back as converged, prints each unverified window with what it reads, and exits 1 — the second writer was the screen title escape under `allow-rename on`, so a pfm rename now latches `allow-rename off` on that window (issue #14 F11, F12, F13).

- C: repo — `dev.sh test` names an uninstalled walker as a `GAP` line and exits non-zero (an offline `npm ci` is tried first); `/pfm:release` stamps the self-hosted install ledger as a gated step before the release commit; the `ptm-guard.sh` transitional shim is deleted end to end (issue #14 F2, F3, F7, F8).

## Fixed

- C: pfm — a delivered message's reply hint names a chat the fleet resolves, never its tmux socket. The inject footer now reads the sender's LABEL afresh for every delivery — from the fleet roster first (the exact-name rung a peer's `chat_inject` matches, via the new `resolve.ResolveRosterSeat` reverse lookup on both the MCP and CLI doors), then the sender's own 🔖 statusline, then the codex window name — instead of a screen scrape cached once per process, which left one chat's MCP server signing every message for a day as `to reply: chat_inject cc-…` after its first capture landed seconds after a reload with no statusline on screen. Without a label the hint falls back to the sid (the same eight characters the footer already shows, which the roster resolves as an id prefix); a sender with neither is UNSIGNED and says so. A rename now reaches the footer on the next delivery, and the comms ledger records the label the cosmos draws edges by.

- A: pfm — the statusline's `💾` cache timer is never width-gated: it shared the `COLUMNS ≥ 100` gate with the token count, so a 97-column VS Code pane lost the timer entirely — a missing timer is indistinguishable from an expired one nobody rendered. The token count keeps the gate; the dead `output_style` payload field is gone (issue #14 F4).

- C: pfm — the cosmos golden was right and the renderer was arch-dependent: Go contracts `a*b+c` into a fused multiply-add on arm64, and the quadratic Bézier rail landed one dot a cell over; `bezierAt` rounds every product explicitly (`float64()`), with a go/ast test that fails on any arch if the barrier is removed (issue #14 F9).

- A: pfm — `pfm --version` after `make build` / `make host-install` reports the stamped release; an unstamped build says `dev (<revision>, modified)` from the module's VCS info, never a bare `dev` (issue #14 F6).

- A: pfm — the idle `pfm ls` picker parks at ~1% of a core instead of 57% on a live fleet, and the installer owns VS Code's terminal-persistence keys in the remote `Machine/settings.json`.

## Removed

- A: pfm — `pfm revive`, `cc-revive`, and `vsct-revive` are removed: a VS Code tab is only a window onto a chat's own tmux socket, and a lost tab is reopened from `pfm ls`, never revived.
