# v0.49.0 — 2026-08-04

The host-swap fleet claimed Linux **and** macOS from its first line. It ran on Linux. Eight
distinct Linux-only assumptions meant a Mac got empty answers instead of errors — the failure mode
that reads as "you have no chats" rather than as a bug. This release makes the claim true and puts
the whole GNU/BSD divide behind one file.

## Added

- Blueprint: `templates/host-swap/cc-portable.sh` — the GNU/BSD seam. Every question whose answer
  differs between Linux and macOS is asked here once and nowhere else: `cc_mtime`/`cc_size`
  (`stat -c` vs `stat -f`), `cc_epoch` (`date -d` vs `date -j -f`, fractional seconds and the `Z`
  trimmed before BSD's parser sees them), `cc_find_meta`/`cc_find_newest` (`find -printf` vs a
  batched `stat` exec), `cc_trylock`/`cc_unlock` (`flock` vs an atomic `mkdir` with a pid-owner
  file), `cc_detach` (`setsid` vs `nohup`), `cc_timeout` (`timeout`/`gtimeout`/run-anyway),
  `cc_ppid`/`cc_pstart`/`cc_children_args`/`cc_pfiles` (`/proc` vs `ps`/`lsof`), `cc_pane_of`,
  `cc_session_live`, `cc_listening` (`ss` vs `lsof`), `cc_mem` (`free` vs `vm_stat`), and
  `cc_sed_i`. Written in POSIX sh on purpose: the zsh launcher and the bash scripts share ONE
  implementation instead of drifting two. The GNU form is always tried first, so Linux pays
  nothing for the portability. (safe-auto)
  #### → For: re-run `blueprint/templates/host-swap/install.sh --apply` once — this release ADDS a file, so the installer reports one new link and leaves every other link alone. Nothing else changes for a Linux adopter; no behavior on that platform is different.

- Blueprint: three laws the seam enforces, each earned by a bug in this release. **A function that
  cannot answer returns empty, never a plausible value** — a fabricated `0` mtime sorts a live chat
  to the bottom of the picker instead of admitting the stat failed. **Where macOS genuinely cannot
  answer, the caller asks a better question** rather than accepting the degraded one — see
  `cc_pane_of` below. **One mechanism per platform, not two** — a Linux `flock` holder and a macOS
  `mkdir` holder cannot see each other, which is how you get two processes both holding "the" lock.

## Fixed

- Blueprint: `find -printf` is GNU-only — six sites, and the two that mattered most were the
  **entire chat index**. `cc-ls` builds its list with `find … -printf '%T@\t%s\t%p\n'`; BSD find
  rejects `-printf` outright, so on a stock Mac the scan produced nothing, the picker listed no
  chats, and `cc-name-sync` could not match a single codex thread to its pane. Nothing errored.
  Now routed through `cc_find_meta`, whose BSD arm gets the same three fields from one batched
  `stat` exec — one process per scan, not one per file. Verified identical on both arms (143 rows,
  same order; BSD reports whole-second mtimes, so same-second ties order by size instead of
  sub-second time, which nothing in the bundle can observe). (safe-auto)

- Blueprint: `flock` is not on macOS, and `cc-name-sync.sh` opened with
  `exec 9>"$LOCK" 2>/dev/null && flock -n 9 || exit 0`. The missing binary failed the `&&`, so the
  `||` fired and **the entire script exited before doing any work** — silently, with status 0, on
  every single run. Codex windows never got their names and nothing anywhere said why. Replaced
  with `cc_trylock`, an atomic `mkdir` holding a pid-owner file so a lock left by a crash is stolen
  rather than honoured forever, plus an EXIT trap to release. (safe-auto)

- Blueprint: `setsid` is not on macOS either — and it prefixes every helper this bundle detaches to
  outlive the very pane it is about to kill: `/bb`'s exit-and-clean, `/swap`'s reboot,
  `/chat:inject --then`'s follow-up turn. None of them ever ran on a Mac; a chat asked to close
  simply stayed open. `cc_detach` emits the prefix (`setsid` where it exists, else `nohup`, which
  is POSIX and buys the property that actually matters here — immunity to the SIGHUP that arrives
  when the pane dies). (safe-auto)

- Blueprint: reading another process's environment is impossible on macOS, and six sites depended
  on it. SIP has restricted `ps -E` to the calling process for a decade, so `/proc/<pid>/environ`
  has no equivalent and every one of those reads came back empty — which the callers took to mean
  "the variable is unset" when it meant "we cannot see". Three consequences, each a wrong answer
  rather than a missing one: a codex-origin `/bb` measured "no ancestor is in tmux" and aborted; a
  `cc-ls` ⚙ row sent a resident chat down the takeover path instead of an attach; and **every
  background agent defaulted to account 1**, sending a takeover to the wrong subscription. Two of
  the three are now asked differently: `cc_pane_of` asks the tmux servers which pids they own and
  walks the same ancestry — portable, and truer besides, since a pane whose command re-execs keeps
  its pane while the original env may name a server that no longer holds it. Agent ownership now
  comes from the per-session `session-env/<id>` breadcrumb every launch already writes: an on-disk
  fact, readable on any platform, true even for a chat whose process the scan cannot see. The one
  irreducible case — a chat's birth cache-mode — degrades in the safe direction and says so in
  place: unreadable and flagless produce the same verdict, so the only chat a Mac reads wrong is
  one deliberately born 5m, which it treats as 1h rather than promising a cheaper window than the
  chat actually has. (safe-auto)

- Blueprint: the ordinary GNU/BSD spelling splits, all now behind the seam — `stat -c` (7 sites),
  `date -d` (2), `ps --ppid` (1), `free -m` (2), `ss -ltn` (1), `timeout` (3), and `find -printf '%f'`
  in `cc-db.sh`'s index prune, which emitted nothing on BSD and so silently pruned the whole index.
  Two `env -u VAR cc_timeout …` call sites became subshells, because `env` execs a binary and
  cannot see a shell function. (safe-auto)

- Blueprint: `_cc_label` reported the primary account as "(not logged in)" — on **every** platform.
  It read `"$dir/.claude.json"` uniformly, but Claude Code keeps the DEFAULT account's identity at
  `~/.claude.json`, beside the config dir rather than inside it; `~/.claude/.claude.json` does
  exist and holds only machine state (`machineID`, `projects`, `seenNotifications`), no
  `oauthAccount`. So the lookup found a real file, no email, and rendered account 1 as logged out
  while `cc1` logged in perfectly well. Accounts 2+ are explicit `CLAUDE_CONFIG_DIR`s and do keep
  the file inside, so only slot 1 is special-cased — the same rule the statusline badge already
  followed. (safe-auto)

- Blueprint: the four fixtures were themselves Linux-only and blamed innocent code for it. BSD
  `wc -l` right-pads its count (`"       2"`), macOS resolves `/var` through `/private/var` while
  `tmux` reports `pane_current_path` physically, and `touch -d @EPOCH` / `date -d @EPOCH` are GNU
  forms whose failure was a usage block on stderr and a carry-on — so every rollout kept the wrong
  mtime and no codex pane ever matched its thread. 45 assertions failed on macOS pointing at code
  that was correct. A fixture that cries wolf on one platform is worse than no fixture: it trains
  you to skim the failures. **106 assertions, 0 failures** on macOS 15 (Darwin 25) and unchanged on
  Linux. (safe-auto)

- Blueprint: `tests/install-fixtures.sh` wrote a `SENTINEL-$$` line into the **real clone** to prove
  "edit the bundle, the live command changes", then removed it with a GNU-form `sed -i` that BSD
  sed rejects (it reads the expression as the backup suffix and waits on stdin). On macOS the
  removal silently failed and the fixture left a sentinel behind in a tracked source file on every
  run. It now installs a sandbox copy, proves the property there, and asserts the clone was
  untouched. (safe-auto)

## Changed

- Blueprint: `templates/host-swap/README.md` — the opening claim of Linux + macOS support now says
  what backs it: which tools differ, which four binaries macOS does not ship at all, that the one
  question macOS cannot answer returns empty rather than a guess, and that the `systemd/`
  name-sync triggers are the single platform feature with no macOS equivalent (the installer
  already skips them with a line saying the sync still fires from every `cc-ls` run). The file
  table gains `cc-portable.sh`.
