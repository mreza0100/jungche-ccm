## Added

- Added: `pfm doctor` reports the Codex pane bindings against each other — two panes on one thread,
  a pane bound to a thread a clear already retired, and every live pane pfm currently cannot follow
  through a clear. All three were invisible on every surface until now; the first two were found by
  reading the meta table by hand.

## Changed

- Changed: `pfm chat inject` REFUSES to send when no sender identity can be derived, instead of
  delivering the message stamped `UNSIGNED — sender identity underivable`. An unsigned message asks
  its recipient to act on an instruction from nobody, and the recipient's only defensible answer is
  to distrust it — so the send accomplished nothing except to look like it worked. The refusal fires
  at the sender, the one party who can still repair the identity.

  #### → For: a detached or environment-scrubbed caller (`setsid`, `nohup`, a disowned worker) must
  now state its identity — `CHAT_SENDER_SESSION=$(pfm whoami) CHAT_SENDER_LABEL=<label> <command>` —
  or pass the new `pfm chat inject --allow-unsigned` to send anyway. Sends from inside a chat are
  unaffected.

- Changed: `pfm chat reload` takes `--account N`; every setting is now a flag and there are no
  positional arguments. A rejected word is answered with the flag it should have been
  (`cache off` → `--1h off`) rather than a bare usage line, and the command card states that the
  calling chat's own pane is detected automatically so `--sock` is never needed to reload yourself.
  The bare positional account number still works.

- Changed: `pfm` picker — a lone `{GROUP}:{NAME}` chat gets its group panel and indent immediately
  instead of sitting flat until a second member arrives and re-lays out the list. The prefix rule
  tightened to match: a group is a whitespace-free prefix, a colon, and a non-empty name, so
  `fix: the bug` stays the sentence it is.

- Changed: the shipped personas drop their two-depth split — each Tier A persona now ships as ONE
  file (`professor.md`, `jc.md`) carrying the lean voice plus the full behavioral contract, instead
  of a `full`/`compact` pair chosen at install. The install-time depth question is gone with it.

  #### → For: an existing install keeps whichever variant it copied; nothing breaks. A re-install or
  `/pcm:update` picks up the single file. There is no longer a second variant to switch to.

- Changed: SETUP question 5 (the Professor's ten disciplines) is retired. The persona's
  qualification is fixed prose — a polymath with 15+ PhDs, one in whatever area the work touches —
  so there is nothing to collect. The question NUMBER is kept so `--re-interview N` stays stable for
  questions 6 and up.

## Fixed

- Fixed: `pfm` Codex `/clear` — a chat's display NAME can no longer move its pane binding. Codex's
  index lags a post-clear rename by one refresh, so for that window the name resolved to exactly
  one thread: the dead pre-clear one. The pass took that as the pane's identity, walked the binding
  BACKWARD onto the corpse, and clear-killed the live thread that had replaced it — after which
  `pfm chat resolve` answered with the dead thread and every inject landed where nobody was. A name
  may now SEED an unbound pane and nothing more; only a bare thread id observed on the pane's own
  status line — which is exactly what a post-clear thread shows, because it is unnamed — may move a
  binding.

- Fixed: `pfm` Codex `/clear` — one thread can no longer be bound to two panes. Two panes sharing a
  display name both resolved to the single thread that carried it, so the fleet followed one of them
  into a chat it was not running. The incumbent keeps the thread; a second claimant is refused and
  says so.

- Fixed: `pfm` Codex `/clear` — a resume or fork, which lands a CHILD rollout in the same pane and
  looks exactly like a clear from the status line, no longer retires the chat's own lineage root and
  makes the chat vanish from the fleet. The lineage is consulted, and a lineage that could not be
  READ refuses the kill rather than guessing.

- Fixed: `pfm` Codex `/clear` — a pane binding that points at a thread a clear already retired is now
  DROPPED. That binding is impossible, and it was also a trap: from then on the pane shows a name,
  and a name may not move a binding, so nothing could ever move it off the dead thread. Dropping it
  returns the pane to unbound — the honest answer — and its own status line re-seats it. An
  unreadable kill table drops nothing, and an explicit `pfm chat kill` (which hides a chat that is
  still running) is not a retirement.

- Fixed: `pfm doctor` counts a Codex pane binding whose PANE is gone as stale rather than contested,
  and reports the split (`total / live / stale / contested / retired`) so the numbers reconcile. The
  binding table outlives its panes — a real host held 76 bindings for 19 live panes — so the first
  cut of this check reported eight fleet-wide collisions that were entirely dead-pane litter. A
  check that cries wolf fails the same way as one that stays silent.

- Fixed: `pfm doctor` no longer says a binding "was dropped" when it did not drop one. The reason
  string is shared with the reconcile pass, which is the only writer; the read-only report now
  states the condition and the pass states the write.

## Removed

- Removed: Dr. House is no longer shipped in the blueprint. The archetype was a `/pcm` overlay for
  THIS repo's own framework surgery, which is not work an adopter's install does; the pointers that
  named it are removed with it rather than left dangling.

## Migration

- Migration: `v0.63.0` → `v0.64.0` — no commands are added or retired. Two behavior changes are
  deliberate and will be noticed. `pfm chat inject` now REFUSES an unsigned send rather than
  delivering it with an `UNSIGNED` stamp, so any caller that injects from a detached or
  environment-scrubbed process must state its identity or opt in explicitly. And `pfm chat reload`
  no longer accepts loose words in an argument position — every setting is a flag.

  #### → For: replace the binary, run `pfm install --yes`, and **exit every running `pfm ls`
  first** (see the runbook — a live picker executes the deleted old binary and will undo the
  `/clear` repair). Then audit anything that calls `pfm chat inject` from `setsid`, `nohup`, cron,
  or a disowned worker: it must export `CHAT_SENDER_SESSION`/`CHAT_SENDER_LABEL` or pass
  `--allow-unsigned`.

### LLM upgrade runbook

This is the complete execution contract for an LLM upgrading Professor to v0.64.0. This release is
six corrections to Codex `/clear` identity, one new diagnostic, three surface changes, and one
retirement from the shipped blueprint. It adds no commands. The one step that is easy to skip and
expensive to skip — killing stale pickers — is first, not last. Preserve unrelated work.

#### 1. Exit every running dashboard BEFORE anything else

This release repairs state that a running dashboard writes on every refresh, and a dashboard that
was already running does not reload a replaced binary — it keeps executing the deleted old one.
On a real host a `pfm ls` left running for two days re-created the exact bindings this release drops,
once per refresh, making a verified fix look like it had failed.

1. `ps -eo pid,etimes,cmd | grep "[p]fm ls"` — list them with their ages.
2. For each pid, `ls -la /proc/<pid>/exe`. A target ending in `(deleted)` is proof that process is
   running code that no longer exists on disk.
3. Exit or kill each one. This is not optional cleanup; it is a correctness precondition.

#### 2. Inventory before touching anything

1. In the Professor source clone and every checkout sharing its Git directory, run
   `git status --short`. Stop if the update clone is dirty; do not reset, delete, or stash another
   session's work.
2. Grep your automation for `pfm chat inject`. Any call site that runs detached (`setsid`, `nohup`,
   `&` + `disown`, a systemd unit, cron) or inside an environment-scrubbed tool shell will begin
   FAILING with `refusing to send an UNSIGNED message` instead of silently delivering an unsigned
   one. Record those call sites now; step 5 fixes them.
3. Grep for `pfm chat reload` calls that pass a bare account number. Those still work, but any call
   passing loose words in an argument position never worked and will now say which flag it meant.

#### 3. Replace the binary, then install

1. Update the source clone to the tag, then build:
   `go -C pfm build -o ~/.local/bin/pfm ./cmd/pfm` (or `pfm update --to v0.64.0`).
2. Preview first: bare `pfm install` is dry-run and names every write. Expect the `/reload` command
   card to be the only content change.
3. Apply: `pfm install --yes`.

#### 4. Verify, and know what each check proves

1. `pfm doctor` — look for the new `codex_pane_bindings` line. It reports
   `total / live / stale / contested / retired / undecodable`. `stale` counts bindings whose pane is
   gone and is expected to be large on a long-lived host; it is history, not a fault. `contested`
   and `retired` are faults, and a non-zero count there names the sockets involved.
2. A `codex_pane=unfollowable` warning is a correct answer, not a failure: it names a live pane whose
   next `/clear` pfm cannot follow, and says why. What would be a bug is silence about such a pane.
3. `pfm chat reload cache off` — must be REFUSED with `"cache" is not a reload argument — did you
   mean --1h on|off?`. If it is accepted or answered with only a bare usage line, the new card and
   binary did not both land.
4. The real test of the `/clear` fix needs a live Codex chat: `/clear` it, then run `pfm ls`. The
   pre-clear row disappears, the chat's name follows onto the new thread, and
   `pfm chat resolve <name>` returns the NEW thread id. If it returns the pre-clear id, step 1 was
   skipped or did not take.

#### 5. Repair detached inject call sites

For every call site recorded in step 2.2, choose one:

- **Preferred** — state the identity at the point where it is still derivable, before detaching:
  `CHAT_SENDER_SESSION=$(pfm whoami) CHAT_SENDER_LABEL=<label> <command>`.
- **Deliberate exception** — `pfm chat inject --allow-unsigned <target> <message>`, which sends and
  warns. Use it only where the recipient genuinely does not need to verify the sender; an unsigned
  instruction is one the recipient should refuse to act on.

#### 6. Adopters of the blueprint

1. `blueprint/output-styles/` now ships `professor.md` and `jc.md` only. If your install copied a
   `.compact.md` or `.full.md` variant, it keeps working — nothing reads the removed names — but a
   re-install or `/pcm:update` will place the single file.
2. Dr. House is no longer shipped. If your install carries `dr-house*.md`, it is yours to keep or
   delete; nothing in the blueprint points at it any more.
3. Run the project's own gate before declaring the upgrade done. A suite you did not watch run is not
   a pass, and a skipped package is a named gap, never a success.
