# v0.52.0 — 2026-08-07

`cc-ls` listed nothing on a Mac. Not "listed fewer chats" — the picker opened with its two ✦
new-chat rows and not one existing chat, on a box with dozens. Three independent faults stacked to
produce that, two of which had been shipping quietly for a while, and one of which had already
written wrong data to disk that fixing the code alone would not have undone. This release fixes
all three, repairs the poisoned cache, and adds the fixture suite that would have caught the worst
of them.

It also makes the fleet read the accounts a box actually HAS rather than a hardcoded 1..4, so a
subscription can be retired without the launchers walking into the hole it leaves.

## Fixed

- Blueprint: `cc-ls` showed **no chats at all** because its reload pipeline still filtered through
  `~/.claude/.cc-ls-hidden` — the pre-database hide list, which `cc-db.sh migrate` **renames
  aside**. So the migration was the thing that broke the picker, on every platform, and the file's
  absence is not a soft failure: `grep -f` on a missing file exits 2 and prints nothing, which
  emptied the whole list. Two details made it survive this long. Pressing ⌃X once recreated the
  file as a side effect, so a box that had ever hidden a chat healed itself and never showed the
  symptom again; and the rows were correct right up to the last step, so every diagnostic short of
  reading fzf's actual input said the picker was fine. The filter now reads a file the picker
  materializes per run from the db-backed hidden set, ⌃X writes through to the db instead of a
  sidecar, and nothing on that path names the retired file. (safe-auto)

- Blueprint: `grep -f` with an **empty** pattern file is not portable, and empty is the common
  case — nothing hidden. BSD and GNU grep read it as "no patterns", so `-v` passes everything;
  ugrep, which a Homebrew `grep` on `PATH` can be, does the exact opposite and passes nothing.
  Every `grep -f` on the picker's path now tests `-s` first and skips the filter when there is
  nothing to filter, which is the only form that means the same thing on all three. (safe-auto)

- Blueprint: `cc_find_meta`'s mtime field carried a fraction on GNU (`find -printf '%T@'`) and not
  on BSD (`stat -f '%m'`), and both callers stripped the fraction with `${line%%.*}` — a pattern
  that is correct on GNU only by accident, because there the first `.` in the line is always the
  fraction separator. On BSD the first `.` is in the PATH, so `mt` came back as
  `"<mtime><TAB><size><TAB>$HOME/"`. That string went into zsh arithmetic (a spray of `bad
  math expression` on stderr) and then **into the persisted chat cache**, where it shifted every
  field one place: `cwd` became a path prefix, `label` became the byte count, and `prompts` became
  0 — and a 0-prompt chat is one the picker deliberately hides. 213 chats were written that way.
  Field 1 is now normalized to an integer epoch **inside the seam**, on both arms, because a
  caller cannot be trusted to re-derive a platform difference; the GNU arm truncates after the
  sort, so sub-second ordering is unaffected on Linux. Both callers split on TAB. (safe-auto)

- Blueprint: `cc-db.sh` gains `chat_gen`, a generation marker on the derived chat cache, because
  fixing the parse above did **not** bring those 213 chats back — the next run found a cache entry
  whose mtime and size still matched the file and trusted it, so the wrong answer survived the fix
  that should have ended it. A cache that outlives the bug that filled it is worse than no cache.
  The table is 100% derived, so the repair is to drop it once and let the scan rebuild; the marker
  makes that happen exactly once per host. `init` stamps a db that has no chat rows yet (a fresh
  install has nothing to repair) and pointedly leaves a populated one unstamped, so re-running
  `migrate` cannot certify the poison as current. `chat-save` additionally refuses any record
  carrying more than six fields rather than storing it shifted. (safe-auto)

- Blueprint: the ⊞ split-window merge read the pane crumbs of the whole tmux SERVER when the
  question is about one SESSION. On a socket carrying several sessions — the plain `default`
  socket does exactly that — every session merged every crumb and rendered the identical "⊞6" row,
  so six unrelated chats appeared as six copies of one row and not one of them was reachable on
  its own. Staleness stays a server question (a crumb is dead only when no session anywhere on
  that server holds the pane); merging is now a session question. A `cc-*` chat server has a
  single session, which is why this never showed there. (safe-auto)

- Blueprint: auto-unhide never took effect once the hide list moved into the database. It rewrote
  the legacy sidecar under a `flock` — a binary macOS does not ship — and never touched the
  in-memory `HID` set, so the `hidden-sync` on the very next line re-sent every uuid it had just
  released. Dropping the uuid from `HID` is now the whole of it, which is also one less lock and
  one less file. (safe-auto)

- Blueprint: `local name` with no assignment, for a name ALREADY local in the same zsh function,
  is a LISTING request — it prints `name=value` on **stdout**. Two such re-declarations inside
  `cc-ls` sprayed `spanes=%0`-style lines through the picker's own output, one per pane. Both are
  gone and the hazard is documented where the locals are declared. (safe-auto)

## Added

- Blueprint: `templates/host-swap/tests/portable-fixtures.sh` — fixtures for the seam, 32
  assertions. Mostly about SHAPE, because that is how the seam fails: not by erroring but by
  handing back something a caller parses into garbage. Field 1 of `cc_find_meta` must be a bare
  integer; field 3 must survive a path full of dots; the scan-line parse is lifted verbatim out of
  the then-active fleet shim and run against a real line, so the test cannot drift away from the code it
  guards. Also pins the two portability facts this release turned up — the empty-`grep -f` split
  and the zsh listing trap — and asserts behaviourally that `cc-ls` with nothing to list prints
  exactly one line, its own.
  #### → For: no action. New file, additive; `install.sh` does not link the fixtures. Run them with `bash tests/portable-fixtures.sh`.

- Blueprint: `_cc_accounts` / `_cc_dir` / `_cc_has` in the then-active fleet shim — the accounts a box
  actually has, discovered from the `~/.cc/N` symlinks rather than hardcoded as 1..4. A slot
  exists exactly when its config dir does. (safe-auto)

## Changed

- Blueprint: everything that offers a choice between accounts now reads that real set. `cc-swap`
  lists only the accounts present and indexes rows by POSITION (with a slot retired, row number
  and account number stop being the same thing); the picker's ⌃S cycles through them, its
  successor map computed in zsh and baked into the bind, which runs under `sh` and cannot ask; a
  stored primary naming a retired slot falls back to the first account that exists; and `_cc_run`
  REFUSES an absent slot, naming the `ln -s` that would add it.

  This is a refusal on purpose. Claude Code's answer to a `CLAUDE_CONFIG_DIR` that does not exist
  is to **create** one, so the alternative to the check is not an error — it is a chat that opens
  at a `/login` prompt with no history, no hooks and no statusline, a brand-new empty account
  wearing the number of one that used to exist.
  #### → For: no action on a box whose accounts are unchanged — `_cc_accounts` reports the same set it always assumed. To retire an account, delete its `~/.cc/N`; to add one, `ln -s <config dir> ~/.cc/N`.

- Blueprint: the picker's glyph legend names only glyphs this box can produce — the `🍀 GPT` entry
  appears only where account 4 exists, the same rule the `⬢` new-chat row already followed for the
  codex binary. A legend entry for a glyph that cannot appear is a promise the picker does not
  keep, on the one line that has to stay readable.

- Blueprint: `templates/host-swap/README.md` — documents that `~/.cc/N` is what makes a slot
  exist, that retiring an account is deleting that symlink, and why the launchers refuse a missing
  one rather than creating it. The fixtures list and the `tests/` row gain the seam suite.
