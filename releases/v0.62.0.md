## Added

- Added: pfm install — opt-in, ownership-aware VS Code terminal profile that opens PFM in new integrated terminals and preserves operator settings across update and uninstall. (opt-in)

- Added: chat MCP — the workflow surface is complete at 27 native tools. `chat_branch`, `chat_goal`, `chat_load`, `chat_self_compact`, and the six-tool group bus (`chat_group_create` / `_invite` / `_ls` / `_read` / `_send` / `_subscribe`) join the existing roster, so every chat workflow except `interrogate` is callable as a tool rather than a slash command.

- Added: `docs/PLACEHOLDERS.md` § Runtime metavariables — registers the ALL-CAPS brace tokens shipped templates carry that SETUP must NOT fill (`{NEW_VERSION}`, `{PID}`, `{SHA}`, `{SEED_*}`, …), each with its owner template and what fills it at runtime. Both classes are now registered, so an unregistered token is genuinely unruled rather than merely uncategorised.

- Added: `docs/PLACEHOLDERS.md` — `{CODEX_MODEL_FRONTIER}` / `{CODEX_MODEL_SPEC}` / `{CODEX_MODEL_COLLECTOR}`, the per-tier Codex model ids the token-ledger `PRICING` notes name; siblings of `{CODEX_MODEL}`. The PhD family is now spelled `_1`…`_10` literally instead of elided, so the registry lists every slot it claims to register.

## Changed

- Changed: `blueprint/agents/reviewer.md` — regenerated verbatim-grade from the live lead-of-seats reviewer (160 lines, up from a stale 97-line v1): hunk ledger, lane seats, the structure/honesty angle seats, a TEST seat, spot-check and fold phases, and the report-as-a-FILE contract. The project's own test gate is the one substituted value (`cd {project} && {PROJECT_TEST_RUNNER}`).

## Fixed

- Fixed: macOS fleet surfaces — provider quota provenance stays truthful, resource readers are platform-native, and picker, updater, and OpenCode index behavior is hardened on Darwin.

- Fixed: quota classification — auth failures require semantic HTTP-auth markers, so digits in credential paths can no longer be mistaken for provider quota rejection.

- Fixed: chat MCP identity — Codex identity is resolved per request, so sender signing and `self` are correct on the shared HTTP transport. Shared HTTP fails closed when `_meta.threadId` is absent; per-chat stdio alone retains ambient identity, and a regression test proves no daemon launcher leaks an identity between seats.

- Fixed: chat capture and inject composer handling — transient overlays and command output are rejected without discarding a real draft.

- Fixed: local MCP daemon exposure — a request carrying an `Origin` header is refused and the SDK's localhost protection is restored, closing the browser and DNS-rebind route into the loopback daemon. Local MCP clients send no `Origin` and are unaffected: no local tool is asked to authenticate.

- Fixed: outbound request safety — the harvest resolver now goes through the SSRF chokepoint instead of around it, and the browser rung's DNS-rebind TOCTOU is closed.

- Fixed: failure states that read as absence — `headless.Inspect` no longer renders a read error as "chat never existed", and `SummarizeStats` distinguishes no-data from all-corrupt instead of rendering them identically.

- Fixed: installer correctness — the legacy carrier migration targets the filename real hosts actually wrote; `pfm-mcp.service` is enabled even when the systemd user manager is unreachable and the Linux daemon restarts after a partial MCP wiring failure; PreToolUse matcher normalization no longer narrows operator-owned hooks; `uninstall()` preflights instead of aborting half-done; `--force` does what it advertises; a malformed `settings.json` degrades the VS Code step rather than the whole install.

- Fixed: `codexgen.RunGlobalAgents` check mode reads the file state it asserts, and `PlanCodex` validates `--effort` before embedding it in a Codex TOML override.

- Fixed: the Codex mirror compiler no longer corrupts filesystem paths that begin with a command name — `/dev/tty` and `/dev/null` survive compilation intact while `/dev build pfm` is still rewritten to its Codex spelling.

- Fixed: `blueprint/refresh-map.json` — every shipped template now carries an entry (131 templates, 131 mapped, none stale); `agents/reviewer.md`, `agents/tracer.md`, `themes/README.md`, and `themes/tokyo-night.json` were unmapped, which is how the reviewer template rotted 63 lines behind its live source unnoticed.

- Fixed: `blueprint/output-styles/professor.full.md`, `blueprint/commands/wave/{orchestrator,live}.md` — prose left ungrammatical or gendered by the founder-name substitution ("He brought the … insight", "is a the user decision", "a mid-batch the user wait").

- Fixed: `INSTALL.md` — the host-fleet surface count read six in one place and seven in two others.

## Removed

- Removed: the host-level `/chat:*` Claude slash-command family — all 19 command cards (`inject`, `ls`, `new`, `read`, `find`, `save`, `load`, `capture`, `goal`, `branch`, `whoami`, `interrogate`, `self:compact`, and the six group verbs) no longer ship, and `pfm install` retires the symlinks it previously wrote under `~/.claude/commands/chat/`. The chat MCP server's tools replace them; `/reload` is now the only command symlink the installer writes. A link the installer does not own is skipped, never deleted. (cost)

- Removed: the bundled chat shell scripts — `chat.sh`, a two-line delegate to `pfm chat` that nothing had called since the Go cutover, is deleted outright; `history.sh` is reimplemented natively as `pfm chat history`, so every chat verb (`find`, `save`, `load`, `branch`, `ls`, `history`) is Go and `pfm/internal/installer/assets/chat/` no longer exists. Output is byte-identical to the retired script, including its no-match error and exit status.

## Migration

- Migration: `v0.61.5` → `v0.62.0` — the `/chat:*` slash commands are gone; drive chat through the MCP tools instead. Run `pfm install --yes` to retire the stale command symlinks; anything you placed under `~/.claude/commands/chat/` yourself is left untouched and must be removed by hand if you no longer want it.

  #### → For: replace the binary, run `pfm install --yes`, then confirm with `pfm ls` and an MCP `tools/list` that the chat server answers. Any prompt, agent, or runbook of your own that types `/chat:inject`, `/chat:ls`, or a sibling must be retargeted to the matching `chat_*` tool.

### LLM upgrade runbook

This is the complete execution contract for an LLM upgrading Professor to v0.62.0. This release
retires the host-level `/chat:*` slash-command family and the last two bundled chat shell scripts,
completes the chat MCP tool surface that replaces them, and closes the seven-day pfm audit. It
changes the host command surface, so the order below is load-bearing: the binary carries the
retirement logic, and an install run by the old binary cannot retire what the new one removed.
Preserve unrelated work and never bypass a failed gate.

#### 1. Inventory before touching anything

1. In the Professor source clone and every checkout sharing its Git directory, run
   `git status --short`. Stop if the update clone is dirty; do not reset, delete, or silently stash
   another session's work.
2. Record what the current install owns, so you can tell a pfm-written link from the operator's own
   file: `ls -la ~/.claude/commands/chat/`. Every entry that resolves into
   `~/.local/share/pfm/install/chat/` is pfm's and will be retired for you. Anything else is the
   operator's and will be SKIPPED — list those paths now and report them at the end; deleting one is
   a data-loss bug, not a cleanup.
3. Exit every running PFM dashboard. A live dashboard does not reload a replaced binary.

#### 2. Replace the binary, then install

1. Update the source clone to the tag, then build: `go -C pfm build -o ~/.local/bin/pfm ./cmd/pfm`
   (or `pfm update --to v0.62.0`). The binary must be replaced BEFORE the install step — the code
   that retires the `/chat:*` links ships inside it.
2. Preview first: bare `pfm install` is dry-run and names every write. Read the retirement lines and
   confirm they match the pfm-owned links you inventoried in step 1.2.
3. Apply: `pfm install --yes`. Expect `~/.claude/commands/chat/` to lose its pfm-owned entries and
   the directory itself to be removed when nothing else remains. A non-empty directory is left in
   place on purpose — that means the operator still has a file there.

#### 3. Restart the daemon and prove the tool surface

1. Restart the MCP daemon so it serves the new binary (`systemctl --user restart pfm-mcp.service`,
   or the launchd equivalent on macOS).
2. Require an MCP `tools/list` to return 27 `chat_*` tools, including `chat_branch`, `chat_goal`,
   `chat_load`, `chat_self_compact`, and the six `chat_group_*` verbs. A short list means the daemon
   is still running the old binary — go back to step 2.1 rather than continuing.
3. Prove the ported verb against a real transcript: `pfm chat history <sid-prefix>` must print the
   transcript header and messages, and an unmatched sid must exit non-zero with
   `no transcript matching sid '…' in any account pool`. An empty result with exit 0 is a
   regression: an error must never render as absence.

#### 4. Rebuild the Codex mirror with the NEW binary

1. `pfm codex build .` then `pfm codex check .`, both run from the repository root and both using
   the replaced binary. Running either with a pre-v0.62.0 binary reintroduces the path corruption
   this release fixes.
2. Verify the fix landed: `pfm/AGENTS.md` must contain `/dev/tty` and `/dev/null` verbatim while
   still rewriting the `/dev` command itself to `$dev build pfm`. Any `$dev/tty` or `$dev/null` in a
   generated file means a stale compiler wrote it.

#### 5. Retarget your own prompts, then verify and close

1. Grep your own prompts, agents, skills, and runbooks for `/chat:` — every hit must be retargeted to
   the matching `chat_*` MCP tool. Injected messages now sign their footer `to reply: chat_inject
   <session> <message>`; a prompt still instructing an agent to type `/chat:inject` will fail
   silently, because the command no longer exists to reject it.
2. Run the project's own gate and watch it to completion:
   `.claude/scripts/dev.sh test pfm` and `.claude/scripts/dev.sh verify blueprint`. A filtered or
   skipped suite is a named gap, never a pass.
3. Require the tagged Release, Installer, and Verify workflows to succeed before accepting the
   release.
