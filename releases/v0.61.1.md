- Fixed: installer migration and preview — recorded-clone `/bb` fossils retire safely; dry-run enumerates exact Codex command, global-agent, MCP, and update-metadata paths, and apply revalidates the same full plan before any host mutation.

- Fixed: Harvester local-source routing — existing and explicit local paths take precedence over scholarly identifier heuristics, so digit-bearing filenames cannot be misclassified as ISBNs before `pfm harvest ask` reads them.

- Fixed: Limits visibility — usage percentages render in stable high-contrast text, while critical values remain bold red without blinking invisible between terminal frames.

### LLM upgrade runbook

This section is the execution contract for an LLM upgrading an existing Professor installation.
Read it completely before changing the machine or an adopter project. The machine PFM lane and
each project's blueprint lane are independent. Preserve local customization, never expose account
or MCP credentials, and report an unavailable check as a named gap rather than a pass.

#### 1. Inventory and preserve the current installation

1. In every source clone and adopter project involved, run `git status --short`. Do not reset,
   delete, overwrite, or silently stash another session's work. Route any required commit through
   that repository's authorized Git writer.
2. Record the installed machine state without printing secrets:

   ```bash
   command -v pfm
   pfm version
   pfm config validate
   pfm config show
   pfm doctor
   pfm mcp ls
   ```

3. Detect project lanes by the presence of `.professor/manifest.json` and `.claude/`. Record each
   manifest version and read every intervening release note before applying semantic migrations.
4. If the machine is on v0.60.0 or older, also read the
   [v0.60.1 one-time updater repair](v0.60.1.md#llm-upgrade-runbook). Do not ask the affected old
   updater to validate its own replacement.

#### 2. Upgrade the machine PFM lane

For an installation already on v0.60.1 or later, use the transactional tagged update:

```bash
pfm update --to v0.61.1
```

Read the candidate build, install, doctor, and rollback receipts. Stop if the source clone is
dirty, the selected tag is not v0.61.1, either reproducible candidate differs, install fails, or
doctor rejects the candidate. Do not replace a failed transaction with a moving-branch build.

For v0.60.0 or older, or when no PFM binary exists, bootstrap the official asset directly:

```bash
PFM_RELEASE_REPO=mreza0100/professor
PFM_RELEASE_TAG=v0.61.1

case "$(uname -s)" in
  Linux)  PFM_RELEASE_OS=linux ;;
  Darwin) PFM_RELEASE_OS=darwin ;;
  *) echo "unsupported operating system: $(uname -s)" >&2; exit 1 ;;
esac
case "$(uname -m)" in
  x86_64|amd64)  PFM_RELEASE_ARCH=amd64 ;;
  arm64|aarch64) PFM_RELEASE_ARCH=arm64 ;;
  *) echo "unsupported architecture: $(uname -m)" >&2; exit 1 ;;
esac

PFM_RELEASE_BINARY="pfm_${PFM_RELEASE_TAG}_${PFM_RELEASE_OS}_${PFM_RELEASE_ARCH}"
PFM_RELEASE_URL="https://github.com/${PFM_RELEASE_REPO}/releases/download/${PFM_RELEASE_TAG}"
PFM_RELEASE_TMP="$(mktemp -d)"
cd "$PFM_RELEASE_TMP"
curl -fLO "${PFM_RELEASE_URL}/${PFM_RELEASE_BINARY}"
curl -fLO "${PFM_RELEASE_URL}/SHA256SUMS"
awk -v file="$PFM_RELEASE_BINARY" '$2 == file' SHA256SUMS > "${PFM_RELEASE_BINARY}.sha256"
test -s "${PFM_RELEASE_BINARY}.sha256"
if command -v sha256sum >/dev/null 2>&1; then
  sha256sum -c "${PFM_RELEASE_BINARY}.sha256"
else
  shasum -a 256 -c "${PFM_RELEASE_BINARY}.sha256"
fi
mkdir -p "$HOME/.local/bin"
install -m 0755 "$PFM_RELEASE_BINARY" "$HOME/.local/bin/pfm"
hash -r
pfm version
```

Stop if the checksum row is absent, checksum verification fails, or `pfm version` does not print
exactly `pfm v0.61.1`. Never substitute an unverified binary.

#### 3. Preview and apply the host reconciliation

Run preview and apply with the same Harvester choice:

```bash
pfm install
pfm install --yes
```

The preview must enumerate concrete writes, links, deletions, and conflicts for embedded assets,
Claude commands, Codex commands and agents, MCP registrations, service units, shell wiring, and
update metadata. Apply must revalidate that complete plan before its first mutation. Stop on any
foreign-file conflict; do not delete or overwrite it merely to make install pass.

Use `--skip-harvest` on both commands only when the operator intentionally leaves the pinned
Harvester runtime unmanaged. Never use it to conceal a failed provision. Professor MCP routes are
loopback-only and unauthenticated by design; do not add tokens or authorization headers.

#### 4. Prove the installed machine behavior

Run:

```bash
pfm version
pfm config validate
pfm config show
pfm doctor
pfm ls --tsv >/dev/null
```

Acceptance requires:

- `pfm version` reports exactly `pfm v0.61.1`.
- Any PFM dashboard that was open during installation has been exited and relaunched; a running
  process does not hot-reload a replaced executable.
- Configuration validation succeeds and retains schema version 2.
- `pfm doctor` reports the configured OpenCode store healthy only after the production reader can
  query native `session`, `message`, and `part` rows and parse their stored JSON.
- `pfm ls --tsv` succeeds against every configured engine. A missing or unreadable store is named;
  it is never flattened into an empty engine.
- Harvester provisioning is healthy. If local-source behavior is in scope, run `pfm harvest ask`
  against a disposable local evidence file and require the chosen Claude or Codex adapter to read
  its contents; preserve the complete failure receipt if it cannot.
- The Limits tab shows every usage percentage without selection or copy highlighting. Values at or
  above the critical threshold remain visible as bold red text rather than blinking.

#### 5. Update each adopter blueprint lane

From each clean adopter project, preview before applying:

```text
/pcm update check --to v0.61.1
/pcm update --to v0.61.1
```

Review both-changed files interactively and preserve every recorded keep-local decision. The
updater classifies release semantics from `## Added`, `## Changed`, `## Fixed`, `## Removed`,
`## Breaking`, and `## Migration`; tier prefixes are labels, not semantic overrides.

After the update, rebuild every enabled runtime mirror from the project's canonical sources:

```bash
pfm codex build .
pfm codex check .
node .claude/scripts/build-opencode.mjs generate
node .claude/scripts/build-opencode.mjs doctor
```

Run the project's own verification gate, inspect `git diff`, and start a new or reloaded session
so Claude, Codex, and OpenCode load the refreshed registry. Never hand-edit generated mirrors.

#### 6. Final acceptance and failure handling

Record the final `pfm version`, `pfm doctor`, `pfm ls --tsv`, installer summary, project gates, and
remaining Git status. Success means the official v0.61.1 binary is installed, all enabled engines
are readable, Harvester is healthy, runtime percentages are visible, and every intended project
lane is either updated or explicitly skipped.

If a transactional update fails, preserve its rollback receipt and confirm the previous binary is
still operational. If direct bootstrap or project migration fails, stop at the first named broken
state; do not claim completion, bypass a checksum or gate, force-reset local work, or mutate a
published tag.
