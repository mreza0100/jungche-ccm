# v0.64.1 — 2026-08-27

## Added

- pcm: `/pcm:release` sweeps every LINKED project's `.professor/release.md`, not only this repo's. `scripts/refresh-scope.sh ledgers <root>…` is the new mechanical reader: it enumerates each named root plus the sub-projects that root's own manifest names by role — already first-class live sources in `refresh-map.json` — and gives every ledger one of four deliberately distinct verdicts. ABSENT means the directory is not a Professor install, EMPTY means the ledger was opened and holds nothing pending, PENDING carries a bullet count and the bullet text, and UNREADABLE means the LOOK FAILED and exits 4, stopping the release. Collapsing that last case into EMPTY is the defect the subcommand exists to prevent: a release may ship with nothing pending, and may never ship because it could not find out. The sweep prints how many ledgers it OPENED, so a release that swept nothing can no longer print the same thing as a release that swept everything — which is exactly what the previous single-ledger flow did, silently, every time. Release step 5 consumes the union and step 9 clears every ledger the sweep reported pending.

  #### → For: pass `--ledger {root}` for any linked project whose pending bullets should ship in this release; the main project and its manifest-named sub-projects are swept without asking.

## Changed

- pfm: the picker's engine colours are an IDENTITY, not a slot in the ramp — Claude a light orange, Codex light blue, OpenCode the green Claude used to carry, in both the row and the stats panel of every palette. A theme restyles the shade, never the hue, so an operator scanning a mixed fleet reads the engine off the colour before reading the row. Two things stopped borrowing an engine's colour in the process: Tokyo Night's agent rows move to the purple Codex vacated, which the re-colour would otherwise have put at the same hex as Claude rows, and the NAME cell of both stats tables — a chat's and a Docker container's — gets its own palette token instead of the Claude row colour both had been reusing. That was harmless while the colours were a ramp and wrong the moment they became an identity: a Codex chat whose name rendered in Claude's orange beside an engine cell rendering blue was a row disagreeing with itself, and a container is not an engine at all. A test asserts that decoupling directly rather than trusting a hex; a test now fails on any palette edit that re-creates that collision, and a second reads the identity as a HUE rather than pinning an exact shade, so a theme tweak stays a theme tweak instead of a test edit.

  #### → For: anyone who reads the fleet by colour — OpenCode takes the green Claude used to wear, Claude lightens to a brighter orange, and Codex turns light blue.

- pfm: a successful self-repair no longer reads like a pair of failures. Dropping an impossible Codex pane binding printed its reason, its consequence, and its action as three separate `tmux probe warning` lines per pane; it is one event and now prints one line naming the repair. A drop that FAILED keeps its own distinct wording, so the surface still separates "we fixed it" from "we tried and could not".

- pfm: `chat_self_compact` tells the caller to persist its own state first. Compaction discards context, and a chat holding a ledger, a handoff file, or a chat-specific memory has exactly one chance to write to it — the focus line and the steers are the only things that cross the boundary. The tool description says so at the point of decision rather than leaving each caller to rediscover it.

## Fixed

- pfm: a Codex pane can be found by the name pfm just gave it. After a `/clear`, the reconcile pass re-applies the chat's established name to the new thread and now records that rename in `cx_names` itself instead of waiting for an index pass to bring it back around. Leaving the record to that later pass set a trap the pass itself sprang: in the window between them the chat's name resolved to exactly ONE thread — the retired pre-clear one — so a pane that lost its binding in that window could not be re-seated, because a name may seed an unbound pane but every thread this name matched was retired. Such a pane reported `status line name matches only threads a /clear already retired` on every refresh and never recovered on its own. pfm authored the rename; it no longer needs a mirror to tell it what it just did.

- pfm: the Codex rename path is testable for the first time. The tmux driver reconcile renames through is now injectable, which is what made the missing name record above provable — before, the one step that has to talk to a live Codex composer had no automated coverage, and neither did anything sequenced after it. The pane fixture these tests share also waits for the pane to PAINT before returning: `tmux new-session -d` returns once the session exists, not once its command has run, so an early capture was byte-for-byte indistinguishable from a pane with no identity — the exact confusion those tests exist to catch, which made the whole file green whether the code was right or merely fast enough. A pane that never paints now fails as a FIXTURE error, in those words.

- pfm: `chat reload --then` now presses Enter on a steer that WRAPS in the composer — which is every steer worth sending after an account switch. Delivery is proven by the prompt's TAIL, the half that proves nothing was truncated in transit, and that proof read the composer's ❯/› MARKER line alone. Claude and Codex print the marker on the FIRST line of a wrapped draft, so the tail of any prompt longer than one row was unreachable: the proof could never be satisfied, pfm refused to press Enter rather than press it blind, and the follow-up sat fully typed in the composer waiting for a human finger. The composer is now read as the BOX it is — the marker line plus every continuation beneath it, ending at the box's horizontal rule so the status rows below stay out — and matched with whitespace removed, so a wrap that lands mid-word (a long path or URL, the substance of most steers) still matches. The fixture that let this ship echoed one hardcoded 17-character prompt onto a single line: it read identically whether the reader handled wrapping or not. It now wraps whatever prompt it is handed, mid-word, at a fixed width, and a regression test watched fail against the one-line reader with the operator's own error text. The submit proof in the same function now reuses that verified tail instead of the prompt's head: evidence seen present and then seen absent is a real transition, while the head was never verified present at all and, in a draft long enough to scroll inside the box, has left view before the first Enter — so its absence reported a submission that never happened.
